# F05 Command line and settings: test plan

## 1. Feature

- ID and name: F05 Command line and settings
- Design: [design.md](design.md), version 1.0

## 2. Cases

The tests call the interfaces of `recipe_menu.settings`, `recipe_menu.app`, and `recipe_menu.cli`, the three new names of `recipe_menu.datafile`, and `python -m recipe_menu`. A unit case calls one interface with inputs that it builds. A functional case runs `main` with a command line, as you type `recipe-menu`, and checks the exit code and the two streams. An integration case reads the example data folder, runs a prototype or a v0.1 scenario at `main`, starts `python -m recipe_menu`, or mixes inputs at random. Each case names the section of the design that it comes from, such as (2.10).

F05 has no real command, because the first one comes with F07. So the tests pass their own stand-in commands to `main` through its parameter `commands` (design section 2), and every functional case runs `main` with them.

The Architect's review of the design (design section 4) and the Architect's list of what PR #34 changes for this plan name cases that the design's examples do not show:

- F05-T28 and F05-T29 hold every row of the Errors table of 2.10, in both languages, with its exact hint line or no second line. `OPTION_NEEDS_VALUE` and `OPTION_TWICE` end with `RUN_HELP_FOR_OPTIONS` for `--lang` and `--data`, and with no line for an option of a command (decision A). The cases test the table, as finding 8 asks, and not the wording of choice 9. F05-T40 holds a `UsageError` that a command's `run` raises, with its own hint or none (2.7).
- F05-T29 holds the three forms of `UNKNOWN_OPTION` in both languages (finding 10). It checks the texts, not whether the Developer builds them from a `Message` or a `Plural`.
- F05-T35 to F05-T37 hold the table of 2.5: `READ`, `CHECK`, and `CREATE`, each with a missing data folder and with settings that have an error, and the `Context.settings` that the command gets in each case (choices 6 and 7, decision B).
- F05-T26 and F05-T27 hold the Architect's model of step 4: `list --lang --lang zh`, `list --lang zh --lang fr`, `list --lang fr --lang zh`, and `list --data` with `RECIPE_MENU_DATA` set.
- F05-T31 holds the forms of rule 4 for a leading `~` and a relative path. It holds the forms of finding 9 by the Interface Designer's answer to question 1 of section 5.
- F05-T32 holds a data folder whose name the system cannot look at, which `os.path.isdir` reports as no folder (step 2).
- F05-T55 and F05-T56 hold random command lines and random settings files, as F04-T58 holds random recipe files.

The design's 12 examples hold 20 `# raises` lines. F05-T01, F05-T02, F05-T03, F05-T14, F05-T15, F05-T17, and F05-T20 hold them all. The other lines of the examples are in F05-T01 and F05-T02 (2.1 and 2.2), F05-T04, F05-T05, F05-T07, F05-T08, F05-T11, and F05-T12 (2.3), F05-T38 (2.4), F05-T13 (2.5), F05-T15 (2.6), F05-T16 (2.7), F05-T18 to F05-T20 (2.8), F05-T51 (2.9), F05-T47 (2.10), F05-T44 (2.11), and F05-T50 (3.1).

Each case calls code that the mock leaves out: `read_settings`, `read_servings`, `main`, `problem_lines`, `first_error`, `stop_at_error`, `Meal.label`, `Meal.heading`, `Command.usage`, `Arguments.option`, `UsageError` and its `text`, or the checks in the constructors of `Settings`, `Command`, and `Arguments`. So each test fails against the mock (R09). The mock defines every constant, such as the members of `Meal`, the defaults of `Settings`, `MIN_SERVINGS`, `MAX_SERVINGS`, `__version__`, and every message, so that the modules import (design section 2). A case that checked only such a constant would pass against the mock. So the cases reach the constants through code that the mock leaves out: the order of `Meal` through `read_settings` (F05-T07), the defaults of `Settings` through `read_settings` (F05-T05), the servings bounds through `read_servings` (F05-T50), and `__version__` through `main(["--version"])` and `pyproject.toml` (F05-T44). Section 4 lists what the mock declares in full. `recipes` keeps its own servings check until the implementation PR, so F04's tests pass against the mock. They must pass after the implementation too, when `read_recipe` reads its servings through `read_servings`.

`tests/f05_support.py` makes no `Command`, `Settings`, or `UsageError` when it is imported. Each of these runs its checks when it is made, and the mock leaves the checks out. A value made at import would stop pytest from collecting the test files, which is an error and not a failing test (R09). So functions or fixtures of the support file make them.

Every case runs on Linux and on Windows. F05-T31, F05-T32, and F05-T48 have a different input or a different expected result on each system, and each says how. On Windows, `Path` compares without case, so a case that checks a path compares `str` of the two paths. A case that builds a path from the current folder takes the folder from `Path.cwd()` after `monkeypatch.chdir`, not from `tmp_path`.

These rules hold for the test data:

- `tests/data/example/` holds the example data folder of `docs/prototypes/example-data.md`, and its `settings.toml` is the one that the prototypes use (architecture 10). The fixture `example_folder` of `tests/conftest.py` copies it to `tmp_path / "recipe-menu"` with LF line ends and gives a `DataFolder` on the copy. The fixture `folder` gives a `DataFolder` on the empty `tmp_path`. "The example folder" and `example` in a case mean the copy.
- F05-T04, F05-T20 to F05-T25, F05-T27, F05-T28, F05-T30, F05-T33, F05-T36, F05-T38 to F05-T42, and F05-T51 to F05-T55 use the example folder. Every other case writes small files of its own into `folder` or into a folder under `tmp_path`.
- The tests write every file as bytes, or with `write_text(text, encoding="utf-8", newline="\n")`, and make its folders first. So a file has the same bytes on both systems.
- No test changes the repository, touches `~/recipe-menu`, or reads the real home folder. Every call of `main` passes `home`, `environ`, and `today`, except that F05-T38 passes `today=None` to read the clock. F05-T48 and F05-T49 start `python -m recipe_menu` with `HOME` and `USERPROFILE` set to a folder in `tmp_path`. A case changes the current folder only with pytest's `monkeypatch.chdir`.

These conventions hold in every case:

- A quoted string in a cell is a Python literal. So `"\u3000"` is U+3000 IDEOGRAPHIC SPACE, `"\u00a0"` is U+00A0 NO-BREAK SPACE, `"\u200b"` is U+200B ZERO WIDTH SPACE, and `"\\"` is one backslash. A TOML value or line in a cell, such as `meals = ["lunch", 3]`, is TOML text. TOML reads `\uXXXX` and `\t` in a basic string as escapes, so a test may write the escape or the character itself.
- In a table cell, `\|` stands for `|`, because Markdown ends a cell at a bare `|`.
- `EN` and `ZH` stand for `Lang.EN` and `Lang.ZH`.
- A problem of `read_settings` is written as its place and its message, such as `meals`: `UNKNOWN_MEAL(meal="supper")`. The place `language` is `BiText("language", "语言")`, `meals` is `BiText("meals", "餐次")`, `meal N` is `BiText("meal N", "餐次 N")`, `servings` is `BiText("servings", "份数")`, and `line N` is `BiText("line N", "第 N 行")`, as `read_toml` gives it. "No place" means that `place` is `None`. Every problem of `read_settings` is an error with the file `settings.toml`. The test compares `str(problem.file)`, and the whole tuple of problems in order, by severity, file, place, `text(EN)`, and `text(ZH)`. "No settings" means that the settings are `None`.
- A message is a name from the tables of the design, with the value of each placeholder. Design 2.3 gives the messages of `settings`, 3.1 the servings messages, 2.8 `FILE_AT_PLACE`, and 2.10 the messages of `cli`. F03 design 2.10 gives `NOT_A_LIST`, `NOT_A_TEXT`, `EMPTY_TEXT`, `ITEM_NOT_A_TEXT`, `EMPTY_ITEM`, and `UNKNOWN_KEY`, F03 design 2.3 gives the messages of `read_toml`, such as `FILE_MISSING`, and F02 design 2.5 gives `RUN_CHECK`, `RUN_HELP_FOR_OPTIONS`, and `RUN_HELP_FOR_COMMANDS`. The English and Chinese texts are the message's two templates with the values filled in. The value `meals` of `UNKNOWN_MEAL` and `NO_MEALS` is `breakfast, lunch, and dinner` and `breakfast、lunch 和 dinner`. `UNKNOWN_KEY(key="K")` in the settings is `Unknown key "K". The keys are L.` and `未知键“K”。可用的键：L′。`, where L and L′ are F02's `and_list` of one list of keys in English and in Chinese, and the list starts with `language`, `meals`, and `servings`, in this order. Before F14 the list is these three keys, as in `Unknown key "K". The keys are language, meals, and servings.` and `未知键“K”。可用的键：language、meals 和 servings。`. F14 adds `dishes` after them, and F16 adds its key (F14 test plan, section 2). So a case checks the start of the list, not the whole list, and compares every other part of the problem in full. The test writes each text out in full as a literal. It imports no message of `settings`, `app`, or `cli`, and none of the servings messages of `datafile`, because they are internal (design sections 2 and 3). It may import the three shared messages of `text`.

These conventions hold for the calls of `main`:

- `home` is `tmp_path / "home"`, an empty folder that the test makes, unless the case says otherwise. "The default folder" is `home / "recipe-menu"`, which is missing unless the case makes it.
- `today` is `date(2026, 11, 10)`, the date of the prototypes. `stdout` and `stderr` are new `io.StringIO` streams, and out and err are their texts after the call.
- `commands` is the v0.1 stand-ins, unless the case names other commands.
- A line such as `list --tag 素` stands for `main(["list", "--tag", "素"], environ=environ, home=home, today=today, stdout=stdout, stderr=stderr, commands=commands)`. `<P>` in a line stands for the argument `str(P)`. "No arguments" stands for `main([], ...)`.
- "In F" means that `environ` is `{"RECIPE_MENU_DATA": str(F)}`. Otherwise `environ` is `{}`, and a line without `--data` runs "with no data folder", because the default folder is missing.
- The result of a call is written `(code, out, err)`. Each line that `main` writes ends with `\n`, and the test compares the whole text of each stream.
- These folders are made under `tmp_path` by the cases that name them. `example` is the root of the example folder. `zh` is a folder whose `settings.toml` holds the line `language = "zh"`. `broken` is a folder whose `settings.toml` holds `meals = ["lunch", "supper"]`. `broken_zh` is a folder whose `settings.toml` holds the lines `language = "zh"` and `meals = []`. `bare` is an empty folder with no `settings.toml`. `missing` is `tmp_path / "missing"`, which does not exist.
- An error with exit code 2 is written as its message with its values, such as `UNKNOWN_COMMAND(command="cook")`. It stands for `(2, "", err)`, where err is the message's English text and then the English text of its hint, each on its own line. "ZH" before it means the Chinese texts. The hint is the one that the Errors table of 2.10 names. `RUN_HELP_FOR_OPTIONS` follows `OPTION_NEEDS_VALUE` and `OPTION_TWICE` of `--lang` and `--data`, `LANG_NOT_EN_OR_ZH`, and `UNKNOWN_OPTION`. `RUN_HELP_FOR_COMMANDS` follows `NO_COMMAND`, `UNKNOWN_COMMAND`, `INCOMPLETE_COMMAND`, `TOO_FEW_ARGUMENTS`, and `TOO_MANY_ARGUMENTS`. `OPTION_NEEDS_VALUE` and `OPTION_TWICE` of an option of a command have no hint, so err is one line. F05-T28 and F05-T29 write every row out in full.
- "`NO_DATA_FOLDER` for P" stands for `(1, "", err)`. In English, err is `There is no data folder at <P>.` and `Run "recipe-menu init" to create it, or name another folder with --data.`. In Chinese, it is `<P> 没有数据文件夹。` and `运行“recipe-menu init”创建它，或用 --data 指定别的文件夹。`.
- `VERSION` is the `version` of `[project]` in `pyproject.toml` at the root of the repository, `Path(__file__).resolve().parents[1]`, read with `tomllib` as UTF-8. `VERSION_LINE` is `f"recipe-menu {VERSION}\n"`, the line that `--version` writes.
- `HELP_EN` is the 21 lines after `PS> recipe-menu --help` in the F05 prototype "Help in English", and `HELP_ZH` is the 21 lines after `PS> recipe-menu --help --lang zh` in "Help in Chinese", each line ended by `\n`. "The English help" and "the Chinese help" of the v0.1 stand-ins are these texts.

A recorder keeps each `(context, arguments)` that it gets, writes nothing, and returns 0, unless the case gives it another behavior. "No stand-in ran" means that every recorder is empty.

## 5. Alignment with the Interface Designer

| Round | Question | Answer |
| --- | --- | --- |
| 1 | Question 1, the leading `~` (Architect review, round 2, finding 9). Rule 4 of 2.10 replaces `~` when `Path(value).parts[0]` is `~`. `pathlib` drops a leading `.`, so `Path("./~/x").parts` is `("~", "x")`, and on Windows `Path(".\\~\\x").parts` is too. So rule 4 as written makes `--data ./~/recipe-menu` count from the home folder. Choice 13 says that `cli` replaces "a leading `~`" and expands no other form. Which does the design mean? Option A: rule 4 as written, so `./~/x` gives `home / "x"`, and choice 13 says that a leading `./` before `~` counts too. Option B: the text of the value decides. It is `~`, or it starts with `~/`, or, on Windows, with `~\`, and only then does `cli` replace the first part with `home`. So `./~/x` names the folder `~` in the current folder, as a shell leaves it. Both options give the same result for `~`, `~/x`, `~\x` on each system, `~troy/x`, and `.`. The Test Manager recommends option B, which matches choice 13 and the way bash and PowerShell read `./~`. F05-T31 input 11 follows the answer. | Option B, from design 1.0. Choice 13 says that `cli` replaces "a leading `~`" and "expands no other form", to do what a shell's own tilde expansion does, because Windows PowerShell 5.1 does not do it. A shell leaves `./~` unchanged. The `--data` row of the parameters table of 2.10 says "A leading `~` counts from the home folder", and the examples of rule 4 are exactly `~`, `~/OneDrive`, and on Windows `~\OneDrive`. The test of `Path(value).parts[0]` in rule 4 was only meant as a way to carry this out, and it overlooked that `pathlib` drops a leading `.` (finding 9). So `./~/x` gives `cwd / "~" / "x"` on both systems. `.\~\x` gives the same on Windows. On Linux, `.\~\x` is one part, so it gives `cwd / ".\\~\\x"`. This answer changes the text of rule 4 of 2.10. The text decides, not `Path(value).parts`, because `pathlib` drops a leading `.`. So `./~/x`, and on Windows `.\~\x`, name the folder `~` in the current folder, as a shell leaves them." F05-T31 input 11 follows this answer, with both `./~/x` and `.\~\x` and the result of each on each system. |
