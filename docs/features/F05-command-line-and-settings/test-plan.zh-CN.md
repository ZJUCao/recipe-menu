# F05 命令行和设置：测试方案

## 1. 功能

- 编号和名称：F05 命令行和设置
- 设计：[design.zh-CN.md](design.zh-CN.md)，版本 1.0

## 2. 用例

测试调用 `recipe_menu.settings`、`recipe_menu.app` 和 `recipe_menu.cli` 的接口，`recipe_menu.datafile` 的三个新名称，以及 `python -m recipe_menu`。单元用例用它自己构造的输入调用一个接口。功能用例像你输入 `recipe-menu` 那样，用一行命令运行 `main`，检查退出码和两个输出流。集成用例读取示例数据文件夹、在 `main` 这一层运行原型或 v0.1 场景、启动 `python -m recipe_menu`，或者随机组合输入。每个用例在括号里注明它来自设计的哪一节，比如（2.10）。

F05 没有真正的命令，第一个命令要到 F07 才有。所以测试通过 `main` 的参数 `commands` 传入自己的替身命令（设计第 2 节），每个功能用例都用它们运行 `main`。

架构师对设计的审查（设计第 4 节）和架构师在 PR #34 里为本方案列出的改动，指出了设计的示例没有展示的用例：

- F05-T28 和 F05-T29 覆盖 2.10 的错误表的每一行，两种语言都有，并带着确切的提示行，或者没有第二行。对 `--lang` 和 `--data`，`OPTION_NEEDS_VALUE` 和 `OPTION_TWICE` 以 `RUN_HELP_FOR_OPTIONS` 结尾；对命令自己的选项，它们后面没有别的行（决定 A）。按发现 8 的要求，这两个用例按表来测，而不是按选择 9 的措辞来测。F05-T40 覆盖命令的 `run` 抛出的 `UsageError`，它带着自己的提示行，或者没有提示行（2.7）。
- F05-T29 覆盖 `UNKNOWN_OPTION` 在两种语言里的三种形式（发现 10）。它检查文字，不检查开发者用 `Message` 还是 `Plural` 来构造。
- F05-T35 到 F05-T37 覆盖 2.5 的表：`READ`、`CHECK` 和 `CREATE`，每种都分别在数据文件夹不存在和设置有错误时运行，并检查每种情况下命令拿到的 `Context.settings`（选择 6 和 7，决定 B）。
- F05-T26 和 F05-T27 覆盖架构师对第 4 步的模型：`list --lang --lang zh`、`list --lang zh --lang fr`、`list --lang fr --lang zh`，以及设置了 `RECIPE_MENU_DATA` 时的 `list --data`。
- F05-T31 覆盖规则 4 对开头的 `~` 和相对路径的各种写法。它按接口设计师对第 5 节问题 1 的回答覆盖发现 9 的各种写法。
- F05-T32 覆盖一个系统无法查看其名称的数据文件夹，`os.path.isdir` 把它报告为不是文件夹（第 2 步）。
- F05-T55 和 F05-T56 覆盖随机的命令行和随机的设置文件，就像 F04-T58 覆盖随机的菜谱文件。

设计的 12 个示例里有 20 行 `# raises`。F05-T01、F05-T02、F05-T03、F05-T14、F05-T15、F05-T17 和 F05-T20 包含了全部这些行。示例的其他行在这些用例里：F05-T01 和 F05-T02（2.1 和 2.2），F05-T04、F05-T05、F05-T07、F05-T08、F05-T11 和 F05-T12（2.3），F05-T38（2.4），F05-T13（2.5），F05-T15（2.6），F05-T16（2.7），F05-T18 到 F05-T20（2.8），F05-T51（2.9），F05-T47（2.10），F05-T44（2.11），以及 F05-T50（3.1）。

每个用例都调用 mock 里没有的代码：`read_settings`、`read_servings`、`main`、`problem_lines`、`first_error`、`stop_at_error`、`Meal.label`、`Meal.heading`、`Command.usage`、`Arguments.option`、`UsageError` 和它的 `text`，或者 `Settings`、`Command` 和 `Arguments` 的构造函数里的检查。所以每个测试对着 mock 都失败（R09）。mock 定义了每个常量，比如 `Meal` 的成员、`Settings` 的默认值、`MIN_SERVINGS`、`MAX_SERVINGS`、`__version__` 和每条提示，让这些模块能够被引用（设计第 2 节）。只检查这样一个常量的用例对着 mock 会通过。所以用例通过 mock 里没有的代码去碰这些常量：通过 `read_settings` 检查 `Meal` 的顺序（F05-T07），通过 `read_settings` 检查 `Settings` 的默认值（F05-T05），通过 `read_servings` 检查份数的上下限（F05-T50），通过 `main(["--version"])` 和 `pyproject.toml` 检查 `__version__`（F05-T44）。第 4 节列出 mock 完整声明的内容。在实现 PR 之前，`recipes` 保留它自己的份数检查，所以 F04 的测试对着 mock 能通过。实现之后，`read_recipe` 通过 `read_servings` 读取份数，F04 的测试也必须通过。

`tests/f05_support.py` 在被引用时不创建任何 `Command`、`Settings` 或 `UsageError`。这些值在创建时运行自己的检查，而 mock 里没有这些检查。在引用时创建的值会让 pytest 无法收集测试文件，那是一个错误，而不是一个失败的测试（R09）。所以由辅助文件里的函数或夹具来创建它们。

每个用例在 Linux 和 Windows 上都能运行。F05-T31、F05-T32 和 F05-T48 在两个系统上的输入或预期结果不同，每个都说明了不同之处。在 Windows 上，`Path` 比较时不区分大小写，所以检查路径的用例比较两个路径的 `str`。用当前文件夹构造路径的用例，在 `monkeypatch.chdir` 之后从 `Path.cwd()` 取得这个文件夹，而不是从 `tmp_path` 取得。

测试数据遵守这些规则：

- `tests/data/example/` 存放 `docs/prototypes/example-data.md` 里的示例数据文件夹，它的 `settings.toml` 就是原型用的那一个（架构 10）。`tests/conftest.py` 的夹具 `example_folder` 把它复制到 `tmp_path / "recipe-menu"`，用 LF 换行，并给出副本上的 `DataFolder`。夹具 `folder` 给出空的 `tmp_path` 上的 `DataFolder`。用例里说的“示例文件夹”和 `example` 就是这个副本。
- F05-T04、F05-T20 到 F05-T25、F05-T27、F05-T28、F05-T30、F05-T33、F05-T36、F05-T38 到 F05-T42，以及 F05-T51 到 F05-T55 使用示例文件夹。其他每个用例都把自己的小文件写进 `folder`，或者写进 `tmp_path` 下的某个文件夹。
- 测试写每个文件时，要么写字节，要么用 `write_text(text, encoding="utf-8", newline="\n")`，并先创建它所在的文件夹。所以同一个文件在两个系统上的字节相同。
- 没有测试改动仓库、碰到 `~/recipe-menu` 或读取真实的主文件夹。每次调用 `main` 都传入 `home`、`environ` 和 `today`，只有 F05-T38 传入 `today=None` 来读取时钟。F05-T48 和 F05-T49 启动 `python -m recipe_menu` 时，把 `HOME` 和 `USERPROFILE` 设为 `tmp_path` 里的一个文件夹。用例只用 pytest 的 `monkeypatch.chdir` 改变当前文件夹。

以下约定适用于每个用例：

- 单元格里带引号的字符串是 Python 字面量。所以 `"\u3000"` 是 U+3000 IDEOGRAPHIC SPACE，`"\u00a0"` 是 U+00A0 NO-BREAK SPACE，`"\u200b"` 是 U+200B ZERO WIDTH SPACE，`"\\"` 是一个反斜杠。单元格里的 TOML 值或行，比如 `meals = ["lunch", 3]`，是 TOML 文字。TOML 把基本字符串里的 `\uXXXX` 和 `\t` 当作转义来读，所以测试既可以写转义，也可以直接写字符本身。
- 在表格的单元格里，`\|` 代表 `|`，因为 Markdown 在单独的 `|` 处结束一个单元格。
- `EN` 和 `ZH` 代表 `Lang.EN` 和 `Lang.ZH`。
- `read_settings` 的一个问题写成它的位置和它的提示，比如 `meals`：`UNKNOWN_MEAL(meal="supper")`。位置 `language` 是 `BiText("language", "语言")`，`meals` 是 `BiText("meals", "餐次")`，`meal N` 是 `BiText("meal N", "餐次 N")`，`servings` 是 `BiText("servings", "份数")`，`line N` 是 `BiText("line N", "第 N 行")`，与 `read_toml` 给出的相同。“没有位置”指 `place` 为 `None`。`read_settings` 的每个问题都是错误，文件都是 `settings.toml`。测试比较 `str(problem.file)`，并按顺序比较整个问题元组，比较每个问题的严重程度、文件、位置、`text(EN)` 和 `text(ZH)`。“没有设置”指设置为 `None`。
- 提示是设计里各张表中的名称，加上每个占位符的值。设计 2.3 给出 `settings` 的提示，3.1 给出份数的提示，2.8 给出 `FILE_AT_PLACE`，2.10 给出 `cli` 的提示。F03 设计 2.10 给出 `NOT_A_LIST`、`NOT_A_TEXT`、`EMPTY_TEXT`、`ITEM_NOT_A_TEXT`、`EMPTY_ITEM` 和 `UNKNOWN_KEY`，F03 设计 2.3 给出 `read_toml` 的提示，比如 `FILE_MISSING`，F02 设计 2.5 给出 `RUN_CHECK`、`RUN_HELP_FOR_OPTIONS` 和 `RUN_HELP_FOR_COMMANDS`。英文文字和中文文字就是提示的两个模板填入这些值后的结果。`UNKNOWN_MEAL` 和 `NO_MEALS` 的值 `meals` 是 `breakfast, lunch, and dinner` 和 `breakfast、lunch 和 dinner`。设置里的 `UNKNOWN_KEY(key="K")` 是 `Unknown key "K". The keys are L.` 和 `未知键“K”。可用的键：L′。`，其中 L 和 L′ 是同一列键用 F02 的 `and_list` 写成的英文和中文，这列键以 `language`、`meals` 和 `servings` 开头，按这个顺序。F14 之前这列键就是这三个，比如 `Unknown key "K". The keys are language, meals, and servings.` 和 `未知键“K”。可用的键：language、meals 和 servings。`。F14 在它们后面加上 `dishes`，F16 加上它的键（F14 测试方案第 2 节）。所以用例检查这列键的开头，而不是整列，问题的其他部分都完整比较。测试把每段文字作为字面量完整写出。它不引用 `settings`、`app` 或 `cli` 的任何提示，也不引用 `datafile` 的份数提示，因为它们都是内部的（设计第 2 节和第 3 节）。它可以引用 `text` 共用的三条提示。

以下约定适用于对 `main` 的调用：

- 除非用例另有说明，`home` 是 `tmp_path / "home"`，一个由测试创建的空文件夹。“默认文件夹”是 `home / "recipe-menu"`，除非用例创建它，否则它不存在。
- `today` 是 `date(2026, 11, 10)`，即原型里的日期。`stdout` 和 `stderr` 是新的 `io.StringIO` 流，out 和 err 是调用之后它们的文字。
- 除非用例指明别的命令，`commands` 是 v0.1 的替身命令。
- 像 `list --tag 素` 这样的一行代表 `main(["list", "--tag", "素"], environ=environ, home=home, today=today, stdout=stdout, stderr=stderr, commands=commands)`。一行里的 `<P>` 代表参数 `str(P)`。“没有参数”代表 `main([], ...)`。
- “在 F 中”指 `environ` 是 `{"RECIPE_MENU_DATA": str(F)}`。否则 `environ` 是 `{}`，这时没有 `--data` 的一行“没有数据文件夹”地运行，因为默认文件夹不存在。
- 调用的结果写成 `(code, out, err)`。`main` 写出的每一行都以 `\n` 结尾，测试比较每个流的全部文字。
- 以下文件夹由提到它们的用例创建在 `tmp_path` 下。`example` 是示例文件夹的根。`zh` 是一个文件夹，它的 `settings.toml` 只有一行 `language = "zh"`。`broken` 是一个文件夹，它的 `settings.toml` 是 `meals = ["lunch", "supper"]`。`broken_zh` 是一个文件夹，它的 `settings.toml` 有 `language = "zh"` 和 `meals = []` 两行。`bare` 是一个空文件夹，没有 `settings.toml`。`missing` 是 `tmp_path / "missing"`，它不存在。
- 退出码为 2 的错误写成它的提示和提示的值，比如 `UNKNOWN_COMMAND(command="cook")`。它代表 `(2, "", err)`，其中 err 是这条提示的英文文字，然后是它的提示行的英文文字，各占一行。前面写着“ZH”时，指中文文字。提示行是 2.10 的错误表为这一行指定的那一条。`RUN_HELP_FOR_OPTIONS` 跟在 `--lang` 和 `--data` 的 `OPTION_NEEDS_VALUE` 和 `OPTION_TWICE`、`LANG_NOT_EN_OR_ZH`，以及 `UNKNOWN_OPTION` 后面。`RUN_HELP_FOR_COMMANDS` 跟在 `NO_COMMAND`、`UNKNOWN_COMMAND`、`INCOMPLETE_COMMAND`、`TOO_FEW_ARGUMENTS` 和 `TOO_MANY_ARGUMENTS` 后面。命令自己的选项的 `OPTION_NEEDS_VALUE` 和 `OPTION_TWICE` 没有提示行，所以 err 只有一行。F05-T28 和 F05-T29 把每一行完整写出。
- “P 的 `NO_DATA_FOLDER`”代表 `(1, "", err)`。英文时，err 是 `There is no data folder at <P>.` 和 `Run "recipe-menu init" to create it, or name another folder with --data.`。中文时，它是 `<P> 没有数据文件夹。` 和 `运行“recipe-menu init”创建它，或用 --data 指定别的文件夹。`。
- `VERSION` 是仓库根目录 `Path(__file__).resolve().parents[1]` 下 `pyproject.toml` 里 `[project]` 的 `version`，用 `tomllib` 按 UTF-8 读取。`VERSION_LINE` 是 `f"recipe-menu {VERSION}\n"`，即 `--version` 写出的那一行。
- `HELP_EN` 是 F05 原型“Help in English”里 `PS> recipe-menu --help` 之后的 21 行，`HELP_ZH` 是“Help in Chinese”里 `PS> recipe-menu --help --lang zh` 之后的 21 行，每行以 `\n` 结尾。v0.1 替身命令的“英文帮助”和“中文帮助”就是这两段文字。
