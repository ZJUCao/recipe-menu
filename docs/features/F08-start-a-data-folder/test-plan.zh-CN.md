# F08 创建数据文件夹：测试方案

## 1. 功能

- 编号和名称：F08 创建数据文件夹
- 设计：[design.zh-CN.md](design.zh-CN.md)，版本 1.0

## 2. 用例

测试调用 `recipe_menu.commands.init` 的 `INIT_COMMAND`，`recipe_menu.datafile` 的 `CreationOutcome`、`Creation` 和 `create_data_folder`，`recipe_menu.cli` 的 `main`，以及 `python -m recipe_menu`。单元用例用它自己构造的值调用 `Creation`、`create_data_folder` 或 `INIT_COMMAND.run`。功能用例像你输入 `recipe-menu init` 那样，用一行命令运行 `main`。它不传 `commands`，所以 `main` 使用真正的 `COMMANDS`，从 mock PR 起 `COMMANDS` 里先是 `INIT_COMMAND`，再是 `CHECK_COMMAND`（设计第 2 节）。集成用例在 `main` 上运行 v0.1 场景，启动 `python -m recipe_menu`，或者随机调用。每个用例在括号里注明它来自设计的哪一节，比如（3.2）。设计的四个示例及其 8 行 `# raises` 分别在 F08-T01（3.1）、F08-T03（3.2）、F08-T14（2.1）和 F08-T15（2.2）里。

**示例文本的两份副本（选择 2）。** F08-T16 用每种语言运行 `init`，把它写出的每个文件与 `tests/data/example/` 里的同名文件逐字节比较，后者按 UTF-8 读取，读出的是 LF 换行。中文的 `settings.toml` 就是英文的那份把 `language = "en"` 换成 `language = "zh"`。F08-T24 和 F08-T26 把整个新文件夹与 F07 的 init 文件夹比较，后者由 `make_init` 从那个示例文件夹的副本构建。F08 的测试都不读 `docs/prototypes/example-data.md`。v0.1-S01 按 v0.1 测试方案所说，把这些文件与那份文档比较。所以只改其中一份副本，总会有测试失败。

**F07 的 init 文件夹和各场景。** v0.1-S01 到 v0.1-S03 以及 v0.1-S06 从 `init` 创建的文件夹开始。F07 测试方案用“init 文件夹”代替这个文件夹，由 `tests/f07_changes.py` 的 `make_init` 从示例文件夹的副本构建。F07-T19 在它上面为 v0.1-S06 运行 `check`，F07-T20 为 v0.1-S01 的步骤 2、v0.1-S02 的步骤 2 和 v0.1-S04 运行 `check`。F08-T24 运行真正的 `init`，检查它创建的文件夹与 `make_init` 构建的文件夹条目相同、字节相同。所以 F07 在 init 文件夹上的每个用例，对 `init` 创建的文件夹也成立。F08-T24 接着在 `init` 创建的文件夹上，于 `main` 运行 v0.1-S01 和 v0.1-S06，期望 F07-T19 所期望的各行。F08-T25 运行 v0.1-S02，F08-T26 运行 v0.1-S03。F08 不重复 v0.1-S04：F07-T20 在相同的字节上检查它的 `check` 步骤，它的 `list` 和 `show` 步骤随 F09 而来。

**R09。** mock 定义了每条消息、带全部字段的 `INIT_COMMAND`、带全部成员的 `CreationOutcome`，并把 `INIT_COMMAND` 加进 `COMMANDS`。它的 `Creation` 没有检查，它的 `create_data_folder` 什么都不碰并给出 `Creation(CreationOutcome.CREATED)`，它的 `run` 什么都不写并给出 0（设计第 2 节）。所以只检查 `INIT_COMMAND` 的字段、`CreationOutcome` 的值、一个合法的 `Creation`、帮助、`init extra` 或 `init --tag`、被拒绝的文件夹保留了它的条目、或者失败什么都没留下的测试，都会在 mock 上通过。每个检查这类内容的用例，也检查 mock 弄错的东西：`run` 的输出，磁盘上的文件，`Creation` 的结果或问题，`Creation` 或 `create_data_folder` 抛出的错误，非 0 的退出码，或者故障工具记录的调用。F08-T01、F08-T14、F08-T17 和 F08-T21 只在一个 mock 会弄错的结果旁边检查这类内容。`tests/f08_support.py` 在被导入时不调用 F08 的任何接口，也不构造 `Creation`。

**两个系统。** 每个用例都在 Linux 和 Windows 上运行，在哪个系统上都不跳过。CI 只在 Linux 上运行，而 R09 把跳过的测试算作没有失败的测试。所以选择 9 的两个用例 F08-T22 和 F08-T23 也在 Linux 上运行，在 Linux 上末尾的空格或点只是名称里的普通字符。它们各自说明在每个系统上期望什么。输出用系统的路径分隔符写出每个文件。所以在用例的输出行里，`recipes/tomato-egg.toml` 代表 `str(Path("recipes", "tomato-egg.toml"))`，`menus/` 代表 `"menus" + os.sep`。新文件夹的表格在两个系统上宽度相同，因为 `recipes/tomato-egg.toml` 和 `recipes\tomato-egg.toml` 都是 23 列宽。在 Windows 上 `Path` 比较时不区分大小写，所以检查路径的用例比较两个路径的 `str`。F08-T05、F08-T08 和 F08-T17 在两个系统上用不同的方法创建悬空链接，F08-T05 和 F08-T17 只在 Windows 上给隐藏文件设置属性。F08-T07、F08-T08、F08-T19 和 F08-T22 期望的问题取决于系统抛出的错误，而两个系统抛出的错误不同，所以它们都按下面“系统给出的消息”所说的方法得到消息。

**用例怎样让磁盘出错。** 设计 3.2 为 `FileExistsError`、`PermissionError` 和其他任何 `OSError` 各有一行，文件夹和文件各一列，还描述了删除失败和 Ctrl+C。这些情况在真实磁盘上很少能按需发生。用例用两种方法得到它们：

- 每个用户在两个系统上都会遇到的真实错误。两个系统都拒绝 300 个字符的名称（设计 3.2 的示例），它对文件夹和文件都给出“其他任何 `OSError`”：在 Linux 上是 `ENAMETOOLONG`，在 Troy 的电脑上是 errno 22。`tests/f05_support.py` 的 `unreadable_name` 在 Windows 上是 `a?b`，在 Linux 上是 256 个字符的名称，它在数据文件夹本身和它上面的文件夹上给出这样的错误。数据文件夹的路径上是一个文件，或者一个指向的不是文件夹的链接，会给出 `NOT_A_FOLDER`。数据文件夹上面的这样一个东西不算缺少的文件夹，所以调用的第一次 `Path.mkdir` 是对紧挨在它下面的路径，这在 Windows 上抛出 `FileNotFoundError`，在 Linux 上，文件下面抛出 `NotADirectoryError`，链接下面抛出 `FileNotFoundError`（第 5 节第 1 轮）。在 Windows 上，选择 9 的名称在 `recipes` 处给出 `FileNotFoundError`。
- 故障工具，用于其他一切情况：另一个程序抢先创建条目引起的 `FileExistsError`，`PermissionError`，`strerror` 为 `None` 或空的错误，写到一半失败，删除失败，列出失败，以及 Ctrl+C。在一次 `create_data_folder` 或 `main` 调用期间，故障工具控制设计 3.2 指明的系统调用，所以错误出现在用例选定的步骤。下一段描述它。

没有用例通过文件系统拒绝访问，无论是用 `os.chmod`、访问控制列表，还是 `tests/f04_support.py` 的 `listing_denied`。Linux 上的 root 用户不受权限位限制，所以依赖权限位的测试以 root 运行时会失败，F04 的测试记过这一点。故障工具给出的 `PermissionError` 对每个用户都一样。所以每个用例在 Linux 上以 root 运行、在 Windows 上以管理员运行时都能通过。

**故障工具。** `tests/f08_support.py` 的 `faults(base, *rules)` 是一个上下文管理器。它打开期间，通过 pytest 的 `monkeypatch` 替换 `os.mkdir`、`os.rmdir`、`os.unlink`、`os.remove`、`os.scandir`、`os.listdir`、`io.open` 和 `builtins.open`，关闭时恢复它们。在 Python 3.13 和 3.14 里，`Path.mkdir`、`Path.rmdir`、`Path.unlink`、`Path.open` 和 `Path.iterdir` 都调用这些函数，内置的 `open` 就是 `io.open`。每个替换函数都调用原来的函数，除非有规则指明这次调用。用例只在它测试的那次调用周围打开故障工具。

- 调用记录是 `base` 下的路径上的调用列表，按顺序排列。每次调用写成一个种类和相对于 `base` 的路径，用 `/` 分隔：`mkdir`、`rmdir`，`os.unlink` 和 `os.remove` 记为 `unlink`，模式里含 `x` 的打开记为 `open`，其他打开记为 `read`。用 `os.scandir` 或 `os.listdir` 列出目录的调用另记一个列表，即“列出记录”。其他路径上的调用，以及故障工具自己做的调用，都不记录。
- 一条规则指明一个种类、一个路径和一个效果，比如 `mkdir R/menus: DENIED`。它的种类是调用记录里的一种，或者 `write`，表示对这个路径的 `open` 所给文件的第一次写入，或者 `list`，表示列出目录。
- 效果是一个异常时，比如 `DENIED`，故障工具抛出它来代替这次调用，所以系统什么都不做。
- `race`：故障工具先像另一个程序那样，用原来的函数自己创建这个条目：对 `mkdir` 创建一个文件夹，对 `open` 创建一个内容为 `b"mine\n"` 的文件。然后它做这次调用，调用抛出系统的 `FileExistsError`。
- `after E`：故障工具做这次调用，关闭 `open` 给出的文件，然后抛出 E。所以条目已经存在，但调用从没拿到它。
- 对于效果为 E 的 `write` 规则，故障工具写出第一次写入的文本的前一半，即 `text[: len(text) // 2]`，刷新后抛出 E。它为这次打开给出的文件对象把其他每个调用都转给真正的文件，关闭它就关闭真正的文件。
- 这些名称代表新的异常。`DENIED` 是 `PermissionError(errno.EACCES, "Permission denied")`，`IO` 是 `OSError(errno.EIO, "Input/output error")`，`NO_SPACE` 是 `OSError(errno.ENOSPC, "No space left on device")`，`CTRL_C` 是 `KeyboardInterrupt()`，`BUG` 是 `RuntimeError("bug")`。`OSError(errno.EIO, "")` 的 `strerror` 是 `""`，`TimeoutError()` 的 `strerror` 是 `None`。

设计 3.2 用 `Path.mkdir` 创建每个文件夹，用 `Path.unlink` 和 `Path.rmdir` 删除，并以 `"x"` 模式打开每个文件。故障工具依赖这些调用，不依赖代码的其他任何细节。

- 给开发者的说明：只有 `create_data_folder` 通过设计 3.2 指明的调用访问磁盘时，这些用例才成立。它用各自的一次 `Path.mkdir` 创建每个文件夹，不带 parents，用 `Path.open` 或 `open` 以 `"x"` 模式打开每个文件，用 `Path.unlink` 和 `Path.rmdir` 删除，用 `Path.iterdir`、`os.scandir` 或 `os.listdir` 列出数据文件夹。在 Troy 的电脑上的 Python 3.13.18 里，`Path.iterdir` 调用 `os.scandir`，`Path.open` 调用 `io.open`，内置的 `open` 就是 `io.open`。设计 3.2 没有指明的调用，比如 `os.open`、`os.makedirs`、`Path.mkdir(parents=True)`、`Path.touch`、`Path.write_text` 或 `shutil`，要么躲开故障工具的规则，要么让调用记录与各步骤不同，所以用例会失败。

抛出 `KeyboardInterrupt` 的用例通过 `pytest.raises` 拿回它，或者从 `main` 得到退出码 130。如果 `KeyboardInterrupt` 反而离开了 `main`，用例把它变成一次失败，所以错误的实现让这个用例失败，而不会中止整个测试运行。

测试数据遵守这些规则：

- `EXAMPLE` 是仓库里的文件夹 `tests/data/example/`，F08-T15 和 F08-T16 读取它，从不修改它。`tests/conftest.py` 的 fixture `example_folder` 把它以 LF 换行复制到 `tmp_path / "recipe-menu"`，并给出这份副本上的 `DataFolder`，F08-T24 把它用作 `example`。
- `home` 是 `tmp_path / "home"`，由 `tests/f05_support.py` 的 `make_home` 创建的空文件夹。“默认文件夹”是 `home / "recipe-menu"`，除非用例创建它，否则它不存在。
- `base` 是每次调用在 `tmp_path` 下自己的一个空文件夹，比如 `tmp_path / "t1"`。`R` 是用例的数据文件夹：`base / "a" / "recipe-menu"`，其中 `a` 不存在，除非用例另有说明。“R 存在且为空”表示 R 是空文件夹 `base / "recipe-menu"`。在规则或调用记录里，`R/menus` 代表 `R / "menus"` 的路径，`a` 代表 `base / "a"`。
- 测试把每个文件写成字节，或者用 `tests/f03_support.py` 的 `write` 写出，后者写 UTF-8 和 LF 换行，并先创建所需的文件夹。所以文件在两个系统上字节相同。
- “P 处的悬空链接”这样创建。在 Linux 上，测试调用 `os.symlink(base / "nowhere", P)`。在 Windows 上，它创建一个新文件夹 T，调用 `_winapi.CreateJunction(str(T), str(P))`，再删除 T，因为符号链接需要 Troy 的账户没有的权限，而目录联接不需要。两个系统上，之后 `os.path.lexists(P)` 为真，`os.path.isdir(P)` 为假。
- “隐藏”的意思是：在 Windows 上，测试用 `ctypes.windll.kernel32.SetFileAttributesW` 设置文件的属性，`0x2` 表示隐藏，`0x6` 表示隐藏和系统。在 Linux 上，`.keep` 开头的点让它隐藏，`desktop.ini` 不设属性。
- “X 的目录树”列出 X 下用 `os.walk(X, followlinks=False)` 找到的每个条目：它相对于 X 的路径、它的种类（文件、文件夹或链接），以及每个文件的字节。它从不跟随链接。“X 的完整记录”还包含每个条目用 `os.lstat` 得到的 `st_mtime_ns`。
- “系统对 C 给出的消息”，其中 C 是一次调用，比如 `os.mkdir(U)`，来自测试在它所测的调用之前自己做 C 时得到的错误。测试先检查 C 抛出 `OSError`，并且什么都没创建。这条消息就是 3.2 的错误表对这个错误的类给出的消息，`os.mkdir` 取文件夹那一列，`open` 取文件那一列：`FileExistsError` 给出 `FOLDER_EXISTS` 或 `FILE_EXISTS`，`PermissionError` 给出 `FOLDER_CREATE_DENIED` 或 `FILE_WRITE_DENIED`，其他任何 `OSError` 给出 `FOLDER_CREATE_ERROR` 或 `FILE_WRITE_ERROR`，其 `reason` 是错误的 `strerror`，`strerror` 为 `None` 或空时是它的类名。所以行和原因都来自系统，用例在两个系统上都成立（第 5 节第 1 轮）。在 Troy 的电脑上，每个这样的调用抛出的错误都属于“其他任何 `OSError`”这一行。对 300 个字符的名称或 `a?b` 做 `os.mkdir` 抛出 WinError 123 的 `OSError`，即 `The filename, directory name, or volume label syntax is incorrect`。以 `"x"` 模式 `open` 300 个字符的名称抛出 errno 22 的 `OSError`，即 `Invalid argument`。在文件、悬空链接或名称以空格结尾的文件夹下面 `os.mkdir` 抛出 WinError 3 的 `FileNotFoundError`，即 `The system cannot find the path specified`。在 Linux 上，256 个或更多字符的名称抛出 `ENAMETOOLONG` 的 `OSError`，即 `File name too long`，在文件下面 `os.mkdir` 抛出 `NotADirectoryError`，即 `Not a directory`，在悬空链接下面 `os.mkdir` 抛出 `FileNotFoundError`，即 `No such file or directory`。测试经理用 Python 3.13.18 在 Troy 的电脑上做了 Windows 的这些调用。还没有人为 F08 在 Linux 上做过这些调用，所以 CI 用 Linux 给出的结果检查这条规则。
- 没有测试修改仓库、碰 `~/recipe-menu` 或读取时钟。每次调用 `main` 都传入 `home`、`environ` 和 `today`，F08-T27 启动 `python -m recipe_menu` 时把 `HOME` 和 `USERPROFILE` 设为 `tmp_path` 里的一个文件夹。用例只用 pytest 的 `monkeypatch.chdir` 改变当前文件夹。

直接调用 `create_data_folder` 时遵守这些约定：

- 对一个 `DataFolder` F，`ITEMS(F)` 是文件夹 `(F.recipes, F.menus, F.shopping)` 和文件 `((F.settings, "s\n"), (F.catalog, "c\n"), (F.pantry, "p\n"), (F.recipe_file("tomato-egg"), "t\n"))`，顺序与 2.2 里调用的表格相同，文本很短。`ITEMS(R)` 代表 `ITEMS(DataFolder(R))`。
- `a` 不存在时，`ITEMS(R)` 的“步骤”是 1. `mkdir a`，2. `mkdir R`，3. `mkdir R/recipes`，4. `mkdir R/menus`，5. `mkdir R/shopping`，6. `open R/settings.toml`，7. `open R/catalog.toml`，8. `open R/pantry.toml`，9. `open R/recipes/tomato-egg.toml`。一个步骤的“删除”，对步骤 1 到 5 是对它的文件夹 `rmdir`，对步骤 6 到 9 是对它的文件 `unlink`。R 存在且为空时，调用先列出 R，并从步骤 3 开始。“步骤 k 处的规则”是种类和路径都与步骤 k 相同的规则。
- 一个问题写成它的文件和它的消息，比如 `menus: FOLDER_EXISTS`，文件为 `Path(".")` 时写成 `.: FOLDER_CREATE_DENIED`。F08 的每个问题都是没有位置的错误。测试检查 `severity is Severity.ERROR`、`str(problem.file)`、`place is None`、`text(EN)` 和 `text(ZH)`。`left` 按它的完整路径的 `str` 组成的元组依次比较。

调用 `main` 时遵守这些约定：

- 像“在 F 里 `init --lang zh`”这样的一行，代表 `tests/f07_support.py` 的 `call(home, ["init", "--lang", "zh", "--data", str(F)], environ)`，它用 `home`、`environ`、`today=date(2026, 11, 10)` 和两个新的 `io.StringIO` 流运行 `main`，不传 `commands`，所以 `main` 使用真正的 `COMMANDS`。“不指定文件夹”的一行没有 `--data`。除非用例给出，`environ` 是 `{}`。`check` 的各行也一样。
- 结果是 `(code, out, err)`。`(c, out L)` 代表 `(c, out, "")`，其中 out 是 L 的各行，每行后面跟着 `"\n"`，此外没有别的。`(c, err L)` 代表 `(c, "", err)`，其中 err 是 L 的各行，每行后面跟着 `"\n"`。`(130, "", "")` 表示退出时什么都没写。

预期文本如下。`{P}` 是 `str(P)`，行里路径中的 `/` 是 `os.sep`。`NEW(P)` 是英文新文件夹的 9 行，即 F08 原型“In English”的第一个输出，用 P 代替 `C:\Users\Troy\recipe-menu`：
