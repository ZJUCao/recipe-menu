# F06 周菜单文件：测试方案

## 1. 功能

- 编号和名称：F06 周菜单文件
- 设计：[design.zh-CN.md](design.zh-CN.md)，版本 1.0

## 2. 用例

测试调用 `recipe_menu.menus` 的接口。F06 没有命令，所以方案里没有功能用例。单元用例用它自己构造的输入调用一个接口。集成用例读取示例数据文件夹，把 `menus` 和 F04、F05 的读取函数连起来，或者通过 F05 的 `problem_lines`、`stop_at_error` 和 `main` 检查原型或 v0.1 场景里的行。每个用例在括号里注明它来自设计的哪一节，比如（2.9）。

架构师的审查（设计第 4 节）有五条 Troy 保持原样的意见，还有两条留给后续阶段的意见。用例在涉及测试的地方覆盖它们：

- 意见 1：星期标签、英文的星期简称和月份名称都是 `menus/messages.py` 里的 `Message` 常量，其他模块不引用它们。用例通过 `Day.label`（F06-T14）、`short_date`（F06-T12 和 F06-T13）、`IsoWeek.date_range`（F06-T10、F06-T11 和 F06-T13）以及问题的位置（F06-T35、F06-T37 和 F06-T41）检查每一段这样的文字。测试把每段文字写成字面量。
- 给开发工程师的意见：`settings=None` 时，日表里的每个未知键都有自己的位置，形式是 `UNKNOWN_KEY.pick(3)`。F06-T38 在一天里放两个未知键，在另一天里放一个，每个都在自己的位置上，文字是“The keys are breakfast, lunch, and dinner.”。F06-T37、F06-T47 和 F06-T55 在有设置时覆盖同样的键。
- 意见 3 是可选的，设计 1.0 保留位置 `周日晚餐，菜品 1`。意见 2、4 和 5 不改变 F06 的任何行为，第 4 节说明了每一条的去处。
- 给后续阶段的意见：mock 定义了每个常量。下面关于 R09 的一段说明用例怎样碰到它们。

用例也覆盖设计提到的年份边界：第 53 周、落在上一年最后一个 ISO 周里的 1 月 1 日、落在下一年第 1 周里的 12 月 29 日到 31 日，以及 9999 年附近的上限（F06-T02 到 F06-T05、F06-T07、F06-T11、F06-T20 和 F06-T22）。没有接口读取今天的日期，所以每个用例都传入固定的 `date`。

设计的 9 个示例里有 18 行 `# raises`。F06-T01、F06-T14、F06-T15、F06-T16、F06-T17 和 F06-T19 包含了全部这些行。示例的其他行在这些用例里：F06-T01（2.1），F06-T09（2.2），F06-T14（2.3），F06-T15（2.4），F06-T16（2.5），F06-T17（2.6），F06-T19（2.7），F06-T23（2.8），以及 F06-T30 到 F06-T32（2.9）。

每个用例都调用 mock 里没有的代码：`IsoWeek.of`、`IsoWeek.parse`、`IsoWeek.dates`、`IsoWeek.date_range`、`IsoWeek` 的 `str`、`short_date`、`Day.label`、`WeekMenu.dishes`、`week_from_argument`、`list_menu_weeks`、`read_week_menu`，或者 `IsoWeek`、`Dish`、`MealSlot` 和 `WeekMenu` 的构造函数里的检查。所以每个测试对着 mock 都失败（R09）。mock 定义了每个常量，比如 `Day` 的成员、`NOT_A_WEEK` 和每条提示，让 `recipe_menu.menus` 能够被引用（设计第 2 节）。只检查这样一个常量的用例对着 mock 会通过。所以用例通过 mock 里没有的代码去碰这些常量：通过 `Day.label`、`IsoWeek.dates` 和 `short_date` 碰到 `Day` 的成员和它们的顺序（F06-T14），通过 `week_from_argument` 碰到 `NOT_A_WEEK`（F06-T19、F06-T21 和 F06-T52），通过读取函数碰到其他每条提示。第 4 节列出 mock 完整声明的内容。

`tests/f06_support.py` 在被引用时不创建任何构造函数会运行检查的值。`IsoWeek`、`Dish`、`MealSlot` 和 `WeekMenu` 的构造函数运行的检查在 mock 里没有，而在引用时创建的值会让 pytest 无法收集测试文件，那是一个错误，而不是一个失败的测试（R09）。所以由辅助文件里的函数或夹具来创建每个 `IsoWeek`、`Dish`、`MealSlot`、`WeekMenu`、`Settings` 和位置，辅助文件在被引用时只保存文字、数字和由它们组成的元组。它在被引用时不调用 `menus` 的任何接口。

除了 F06-T28，每个用例在 Linux 和 Windows 上都能运行。F06-T28 只在 Linux 上运行，在 Windows 上跳过，因为 Windows 上的一个文件夹不能同时放 `2026-W47.toml` 和 `2026-w47.toml`。CI 在 Linux 上运行，所以 CI 会运行并检查它。在 Troy 的电脑上，流程对跳过的测试所做的检查把它列为由 CI 检查。F06-T29 在两个系统上都运行，但每个系统上的预期结果不同，因为 Windows 会把 `menus/2026-w47.toml` 当作周 `2026-W47` 的文件打开，而 Linux 不会（设计选择 1）。F06-T27 在两个系统上用不同的办法禁止列出一个文件夹。F06-T51 和 F06-T52 在 Windows 上预期 `menus\2026-W47.toml`，在 Linux 上预期 `menus/2026-W47.toml`。在 Windows 上，`Path` 比较时不区分大小写，所以检查路径的用例比较两个路径的 `str`。

测试数据遵守这些规则：

- `tests/data/example/` 存放 `docs/prototypes/example-data.md` 里的示例数据文件夹，含 7 个菜谱和菜单 `menus/2026-W47.toml`（架构 10）。`tests/conftest.py` 的夹具 `example_folder` 把它复制到 `tmp_path`，用 LF 换行，并给出副本上的 `DataFolder`。用例里的 `example` 就是这个 `DataFolder`，“示例菜单”就是它的文件 `menus/2026-W47.toml`。夹具 `folder` 给出空的 `tmp_path` 上的 `DataFolder`。
- F06-T23 以及 F06-T28 到 F06-T55 使用 `example`。F06-T33 到 F06-T48 用它们自己的文件替换示例菜单，所以 `example` 的菜谱 ID 仍然是 `list_recipe_ids` 给出的那些。F06-T24 到 F06-T27 把它们的文件写进 `folder.menus`，并先创建这个文件夹。其他用例不使用文件夹。
- 测试写每个文件时，要么写字节，要么用 `write_text(text, encoding="utf-8", newline="\n")`，并先创建它所在的文件夹。所以同一个文件在两个系统上的字节相同。
- 没有测试改动仓库、碰到 `~/recipe-menu` 或读取时钟。F06-T52 像 F05 的用例那样，用固定的 `today` 调用 `main`。
- F06-T32、F06-T44、F06-T48 和 F06-T55 使用 `tests/conftest.py` 的夹具 `default_int_limit`，所以 `PYTHONINTMAXSTRDIGITS` 不会改变它们的结果。

以下值适用于每个用例。测试在测试函数或夹具里创建它们：

- 除非用例另有说明，`week` 是 `IsoWeek(2026, 47)`，`today` 是 `date(2026, 11, 10)`，即原型里的日期。
- `settings` 是 `Settings(Lang.EN, (Meal.LUNCH, Meal.DINNER), 2)`，也就是 `read_settings` 对 `example` 给出的设置（F06-T30）。`every_meal` 是 `Settings(Lang.EN, tuple(Meal), 3)`，和设计 2.9 的示例相同。`dinner_only` 是 `Settings(Lang.EN, (Meal.DINNER,), 2)`，`lunch_only` 是 `Settings(Lang.EN, (Meal.LUNCH,), 2)`。
- `ids` 是由 `list_recipe_ids` 对用例的文件夹给出的 ID 组成的 `frozenset`。对 `example`，它们是 `choy-sum`、`cola-wings`、`mapo-tofu`、`red-braised-pork`、`rice`、`tomato-egg` 和 `tomato-egg-noodles`。
- `D(r, s)` 代表 `Dish(r, s)`。“周一晚餐有 D1 和 D2”指 `menu.dishes(Day.MONDAY, Meal.DINNER)` 是 `(D1, D2)`。“其他每个餐位都是空的”指 `menu.slots` 里其他每个餐位的菜都是 `()`。
- “带有行 L 的文件”先有一行 `week = "2026-W47"`，然后是行 L。“恰好由行 L 组成的文件”只有 L。每行都以 `\n` 结尾。除非用例另有说明，F06-T33 到 F06-T47 把文件写成示例菜单，并调用 `read_week_menu(example, week, settings, ids)`。“用 S”指调用时传入 S 来代替 `settings`。

以下约定适用于每个用例：

- 单元格里带引号的字符串是 Python 字面量。所以 `"\u3000"` 是 U+3000 IDEOGRAPHIC SPACE，`"\u200b"` 是 U+200B ZERO WIDTH SPACE。单元格里的 TOML 行或项，比如 `dinner = ["rice"]`，是 TOML 文字。TOML 把基本字符串里的 `\uXXXX` 和 `\t` 当作转义来读，所以测试既可以写转义，也可以直接写字符本身。
- 在表格的单元格里，`\|` 代表 `|`，因为 Markdown 在单独的 `|` 处结束一个单元格。
- `EN` 和 `ZH` 代表 `Lang.EN` 和 `Lang.ZH`。
- 一个问题写成它的位置和它的提示，比如 `Monday dinner`：`UNKNOWN_RECIPE(recipe="tomato-eggs")`。下面的位置表给出每个位置的 `BiText`。“没有位置”指 `place` 为 `None`。
- 除非用例给出别的文件，`read_week_menu` 的每个问题都是错误，文件是 `menus/2026-W47.toml`，它代表 `Path("menus", "2026-W47.toml")`。`list_menu_weeks` 的每个问题都写明它的文件，比如 `menus/2026-w47.toml`。测试把 `str(problem.file)` 和那个路径的 `str` 比较，并按顺序比较整个问题元组，比较每个问题的严重程度、文件、位置、`text(EN)` 和 `text(ZH)`。“没有问题”指空元组。“没有菜单”指菜单为 `None`。
- 提示是设计里各张表中的名称，加上每个占位符的值。下面的提示表给出填入这些值后的英文文字和中文文字。模板写两个花括号的地方，文字里只有一个，比如 `NOT_A_DISH`。测试把每段文字写成字面量。测试不引用任何提示，只有 `NOT_A_WEEK` 例外，因为 `menus` 为 `week_from_argument` 的调用方导出了它（2.7）。`menus` 的其他提示，以及 `datafile` 里关于读取错误、文件夹和份数的提示，都是内部的（设计第 2 节、F03 设计 2.10 和 F05 设计 3.1）。

2.9 的位置建立在 `Day` 的标签（2.3）和 `Meal` 的标签（F05 设计 2.1）之上。星期标签是 `Monday` 和 `周一`、`Tuesday` 和 `周二`、`Wednesday` 和 `周三`、`Thursday` 和 `周四`、`Friday` 和 `周五`、`Saturday` 和 `周六`，以及 `Sunday` 和 `周日`。餐次标签是 `breakfast` 和 `早餐`、`lunch` 和 `午餐`，以及 `dinner` 和 `晚餐`。
