# F06 Week menu files: test plan

## 1. Feature

- ID and name: F06 Week menu files
- Design: [design.md](design.md), version 1.0

## 2. Cases

The tests call the interfaces of `recipe_menu.menus`. F06 has no command, so the plan has no functional cases. A unit case calls one interface with inputs that it builds. An integration case reads the example data folder, joins `menus` with the readers of F04 and F05, or checks the lines of a prototype or a v0.1 scenario through F05's `problem_lines`, `stop_at_error`, and `main`. Each case names the section of the design that it comes from, such as (2.9).

The Architect's review (design section 4) has five notes that Troy left as they are, and two notes for later stages. The cases cover them where they touch the tests:

- Note 1: the day labels, the short English day names, and the month names are `Message` constants in `menus/messages.py`, which no other module imports. The cases check each of these texts through `Day.label` (F06-T14), `short_date` (F06-T12 and F06-T13), `IsoWeek.date_range` (F06-T10, F06-T11, and F06-T13), and the places of problems (F06-T35, F06-T37, and F06-T41). The test writes each text as a literal.
- The note for the Developer: with `settings=None`, each unknown key of a day has its own place, with the form `UNKNOWN_KEY.pick(3)`. F06-T38 holds two unknown keys in one day and one in another day, each at its own place, with the text "The keys are breakfast, lunch, and dinner.". F06-T37, F06-T47, and F06-T55 hold the same keys with settings.
- Note 3 is optional, and design 1.0 keeps the place `周日晚餐，菜品 1`. Notes 2, 4, and 5 change no behavior of F06, and section 4 says where each one goes.
- The note for the next stages: the mock defines every constant. The paragraph on R09 below says how the cases reach them.

The cases also cover the year edges that the design names: week 53, 1 January in the last ISO week of the year before, 29 to 31 December in week 1 of the next year, and the limits near 9999 (F06-T02 to F06-T05, F06-T07, F06-T11, F06-T20, and F06-T22). No interface reads today's date, so every case passes a fixed `date`.

The design's 9 examples hold 18 `# raises` lines. F06-T01, F06-T14, F06-T15, F06-T16, F06-T17, and F06-T19 hold them all. The other lines of the examples are in F06-T01 (2.1), F06-T09 (2.2), F06-T14 (2.3), F06-T15 (2.4), F06-T16 (2.5), F06-T17 (2.6), F06-T19 (2.7), F06-T23 (2.8), and F06-T30 to F06-T32 (2.9).

Each case calls code that the mock leaves out: `IsoWeek.of`, `IsoWeek.parse`, `IsoWeek.dates`, `IsoWeek.date_range`, `str` of an `IsoWeek`, `short_date`, `Day.label`, `WeekMenu.dishes`, `week_from_argument`, `list_menu_weeks`, `read_week_menu`, or the checks in the constructors of `IsoWeek`, `Dish`, `MealSlot`, and `WeekMenu`. So each test fails against the mock (R09). The mock defines every constant, such as the members of `Day`, `NOT_A_WEEK`, and every message, so that `recipe_menu.menus` imports (design section 2). A case that checked only such a constant would pass against the mock. So the cases reach the constants through code that the mock leaves out: the members of `Day` and their order through `Day.label`, `IsoWeek.dates`, and `short_date` (F06-T14), `NOT_A_WEEK` through `week_from_argument` (F06-T19, F06-T21, and F06-T52), and every other message through the readers. Section 4 lists what the mock declares in full.

`tests/f06_support.py` makes no value at import whose constructor runs checks. The constructors of `IsoWeek`, `Dish`, `MealSlot`, and `WeekMenu` run checks that the mock leaves out, and a value made at import would stop pytest from collecting the test files, which is an error and not a failing test (R09). So functions or fixtures of the support file make each `IsoWeek`, `Dish`, `MealSlot`, `WeekMenu`, `Settings`, and place, and at import the file holds only texts, numbers, and tuples of them. It calls no interface of `menus` at import.

Every case runs on Linux and on Windows, except F06-T28. F06-T28 runs on Linux only and is skipped on Windows, because a folder on Windows cannot hold `2026-W47.toml` and `2026-w47.toml` side by side. CI runs on Linux, so CI runs and checks it. On Troy's PC, the flow's check of skipped tests lists it as checked by CI. F06-T29 runs on both systems with a different expected result on each, because Windows opens `menus/2026-w47.toml` for the week `2026-W47` and Linux does not (design choice 1). F06-T27 denies the listing of a folder in a different way on each system. F06-T51 and F06-T52 expect `menus\2026-W47.toml` on Windows and `menus/2026-W47.toml` on Linux. On Windows, `Path` compares without case, so a case that checks a path compares `str` of the two paths.

These rules hold for the test data:

- `tests/data/example/` holds the example data folder of `docs/prototypes/example-data.md`, with its seven recipes and the menu `menus/2026-W47.toml` (architecture 10). The fixture `example_folder` of `tests/conftest.py` copies it into `tmp_path` with LF line ends and gives a `DataFolder` on the copy. In a case, `example` is that `DataFolder`, and "the example menu" is its file `menus/2026-W47.toml`. The fixture `folder` gives a `DataFolder` on the empty `tmp_path`.
- F06-T23 and F06-T28 to F06-T55 use `example`. F06-T33 to F06-T48 replace the example menu with a file of their own, so the recipe IDs of `example` stay those that `list_recipe_ids` gives. F06-T24 to F06-T27 write their files into `folder.menus`, which they make first. The other cases use no folder.
- The tests write every file as bytes, or with `write_text(text, encoding="utf-8", newline="\n")`, and make its folders first. So a file has the same bytes on both systems.
- No test changes the repository, touches `~/recipe-menu`, or reads the clock. F06-T52 calls `main` with a fixed `today`, as F05's cases do.
- F06-T32, F06-T44, F06-T48, and F06-T55 use the fixture `default_int_limit` of `tests/conftest.py`, so `PYTHONINTMAXSTRDIGITS` cannot change their results.

These values hold in every case. The tests make them in test functions or in fixtures:

- `week` is `IsoWeek(2026, 47)`, and `today` is `date(2026, 11, 10)`, the date of the prototypes, unless the case says otherwise.
- `settings` is `Settings(Lang.EN, (Meal.LUNCH, Meal.DINNER), 2)`, the settings that `read_settings` gives for `example` (F06-T30). `every_meal` is `Settings(Lang.EN, tuple(Meal), 3)`, as in the design's example of 2.9. `dinner_only` is `Settings(Lang.EN, (Meal.DINNER,), 2)`, and `lunch_only` is `Settings(Lang.EN, (Meal.LUNCH,), 2)`.
- `ids` is `frozenset` of the IDs that `list_recipe_ids` gives for the folder of the case. For `example`, they are `choy-sum`, `cola-wings`, `mapo-tofu`, `red-braised-pork`, `rice`, `tomato-egg`, and `tomato-egg-noodles`.
- `D(r, s)` stands for `Dish(r, s)`. "Monday dinner holds D1 and D2" means that `menu.dishes(Day.MONDAY, Meal.DINNER)` is `(D1, D2)`. "Every other slot is empty" means that every other slot of `menu.slots` has the dishes `()`.
- "A file with the lines L" holds the line `week = "2026-W47"` and then the lines L. "A file of exactly the lines L" holds only L. Each line ends with `\n`. F06-T33 to F06-T47 write the file as the example menu and call `read_week_menu(example, week, settings, ids)`, unless the case says otherwise. "With S" means that the call passes S in place of `settings`.

These conventions hold in every case:

- A quoted string in a cell is a Python literal. So `"\u3000"` is U+3000 IDEOGRAPHIC SPACE, and `"\u200b"` is U+200B ZERO WIDTH SPACE. A TOML line or item in a cell, such as `dinner = ["rice"]`, is TOML text. TOML reads `\uXXXX` and `\t` in a basic string as escapes, so a test may write the escape or the character itself.
- In a table cell, `\|` stands for `|`, because Markdown ends a cell at a bare `|`.
- `EN` and `ZH` stand for `Lang.EN` and `Lang.ZH`.
- A problem is written as its place and its message, such as `Monday dinner`: `UNKNOWN_RECIPE(recipe="tomato-eggs")`. The table of places below gives the `BiText` of each place. "No place" means that `place` is `None`.
- Each problem of `read_week_menu` is an error with the file `menus/2026-W47.toml`, which stands for `Path("menus", "2026-W47.toml")`, unless the case gives another file. Each problem of `list_menu_weeks` names its file, such as `menus/2026-w47.toml`. The test compares `str(problem.file)` with `str` of the path, and the whole tuple of problems in order, by severity, file, place, `text(EN)`, and `text(ZH)`. "No problems" means the empty tuple. "No menu" means that the menu is `None`.
- A message is a name from the tables of the design, with the value of each placeholder. The table of messages below gives the English and Chinese texts, with the values filled in. A text has one brace where a template writes two, as in `NOT_A_DISH`. The test writes each text out as a literal. It imports no message, except `NOT_A_WEEK`, which `menus` exports for the callers of `week_from_argument` (2.7). The other messages of `menus` and those of `datafile` for the read errors, the folders, and the servings are internal (design section 2, F03 design 2.10, and F05 design 3.1).

The places of 2.9 build on the labels of `Day` (2.3) and of `Meal` (F05 design 2.1). The day labels are `Monday` and `周一`, `Tuesday` and `周二`, `Wednesday` and `周三`, `Thursday` and `周四`, `Friday` and `周五`, `Saturday` and `周六`, and `Sunday` and `周日`. The meal labels are `breakfast` and `早餐`, `lunch` and `午餐`, and `dinner` and `晚餐`.
