# F04 菜谱文件：测试方案

## 1. 功能

- 编号和名称：F04 菜谱文件
- 设计：[design.zh-CN.md](design.zh-CN.md)，版本 1.0

## 2. 用例

测试调用 `recipe_menu.recipes` 的接口，以及 `recipe_menu.datafile` 的两个新接口：`list_toml_files` 和 `Report.warn`。F04 没有命令，所以方案里没有功能用例。单元用例用它自己构造的输入调用一个接口。集成用例把几个接口连起来、读取示例数据文件夹，或者在读取函数这一层检查原型或 v0.1 场景里的行。每个用例在括号里注明它来自设计的哪一节，比如（2.6）。

架构师对设计的审查（设计第 4 节，第 1 轮和第 2 轮）列出了设计的示例没有展示的用例：

- F04-T29 和 F04-T30 是架构师模型里的步骤：`zh = ""`、`zh = " "` 和 `zh = 3` 在 `steps` 处给出 `NOT_A_LIST`，`zh = []` 给出警告 `NO_ZH_STEPS`，`zh = [" "]` 在 `Chinese step 1` 处给出 `EMPTY_ITEM`，`zh = ""` 加上 `en = []` 不给出 `NO_STEPS`。
- F04-T15 和 F04-T27 是名称和备注里空白的文字，它仍然算作缺失这种语言。
- F04-T18、F04-T19 和 F04-T41 是提示会显示的最多 15 位的数字，以及任何提示都不显示的 5,000 位十六进制整数。
- F04-T50 和 F04-T51 是 `TOML_ENDING_NOT_SMALL` 的排序依据，接口设计师已在第 5 节确定：整个条目名称，按 `str` 比较。
- F04-T12 和 F04-T51 只在 Linux 上运行，原因在于 Windows 对设备名和名称大小写的处理。
- F04-T58 是随机的菜谱文件，就像 F03-T86 是随机的目录。

设计的 9 个示例里有 13 行 `# raises`。F04-T01、F04-T03、F04-T04、F04-T05、F04-T42 和 F04-T48 包含了全部这些行。

每个用例都调用 mock 里没有的代码：`is_recipe_id`、`list_recipe_ids`、`read_recipe`、`read_recipes`、`list_toml_files`、`Report.warn`、`Steps.get`、`Steps.exact`，或者 `RecipeIngredient`、`Steps` 和 `Recipe` 的构造函数里的检查。所以每个测试对着 mock 都失败（R09）。`Report.add`、`read_list`、`read_table`、`read_text` 和 `report_unknown_keys` 从 `catalog` 移过来（设计 3.2），mock 保留它们的函数体，让 F03 的测试仍然通过。单独测它们的用例对着 mock 会通过，所以没有用例这样做。F04-T55 只在 `warn` 前后调用它们。第 4 节列出 mock 完整声明的内容。

除了 F04-T12 和 F04-T51，每个用例在 Linux 和 Windows 上都能运行。这两个用例只在 Linux 上运行，在 Windows 上跳过，每个都说明了原因。CI 在 Linux 上运行，所以 CI 会运行并检查它们。在 Troy 的电脑上，流程对跳过的测试所做的检查把它们列为由 CI 检查。F04-T36、F04-T52 和 F04-T53 在两个系统上用不同的办法引发 `OSError`，F04-T13 和 F04-T52 在两个系统上得到不同的 `OSError`。这几个用例都说明了做法。

测试数据遵守这些规则：

- `tests/data/example/` 存放 `docs/prototypes/example-data.md` 里的示例数据文件夹，含 7 个菜谱（架构 10）。`tests/conftest.py` 的夹具 `example_folder` 把它复制到 `tmp_path`，用 LF 换行，并给出副本上的 `DataFolder`。夹具 `folder` 给出空的 `tmp_path` 上的 `DataFolder`。所以没有测试改动仓库或碰到 `~/recipe-menu`。用例里说的“示例文件夹”就是这个副本。“示例目录”是 `read_catalog` 对示例文件夹给出的目录，它没有问题（F03-T48）。
- F04-T09、F04-T37 到 F04-T44、F04-T47、F04-T48 和 F04-T57 使用示例文件夹。其他每个用例都把自己的小文件写进 `folder` 的 `DataFolder`，或者写进它指明的、建在 `tmp_path` 某一部分上的 `DataFolder`。
- 测试写每个文件时，要么写字节，要么用 `write_text(text, encoding="utf-8", newline="\n")`，并先创建它所在的文件夹。所以同一个文件在两个系统上的字节相同。

以下值和文件适用于每个用例：

- 有些值来自设计里的示例，测试照设计的写法构造它们。`produce`、`tomato` 和 `wedges` 来自 2.1。`chinese` 和 `both` 来自 2.2。`choy_sum`、`quick`、`name`、`lines` 和 `steps` 来自 2.3。
- `dish_catalog` 是 `Catalog((produce, eggs), (tomato, egg, scallion), (quick, home))`，其中 `eggs = Category("eggs", BiText("Eggs, dairy, and tofu", "蛋奶豆制品"))`，`egg = Ingredient(BiText("Egg", "鸡蛋"), eggs, Unit.PIECE)`，`scallion = Ingredient(BiText("Scallion", "葱"), produce, Unit.STALK)`，`home = Tag(BiText("home-style", "家常"))`。所以 `tomato` 没有默认单位。
- “基础菜谱”是下面这个文件，写成 `folder.recipe_file("dish")`：

```text
name = { zh = "番茄炒蛋", en = "Tomato and egg stir-fry" }
servings = 2
tags = ["快手"]
ingredients = [
  { item = "番茄", amount = "300 g" },
]

[steps]
zh = ["番茄切块。"]
en = ["Cut the tomatoes."]
```

- `dish` 是基础菜谱给出的菜谱：`Recipe("dish", BiText("Tomato and egg stir-fry", "番茄炒蛋"), 2, (quick,), (RecipeIngredient(tomato, Quantity(Fraction(300), Unit.G)),), Steps(("Cut the tomatoes.",), ("番茄切块。",)))`。“`dish` 加上 `f=v`”指 `dataclasses.replace(dish, f=v)`。
- 用例用这些方式改动基础菜谱：
  - “改为 `name = X`”替换这个键所在的行。`servings` 和 `tags` 也一样。
  - “食材为 A 和 B”把 A 和 B 放在 `ingredients = [` 和 `]` 之间，每项单独一行，缩进两个空格，后面跟一个逗号。“食材为 A”只放 A 一项。
  - “改为 `ingredients = X`”把列表的三行换成这一行。
  - “步骤为 L1 和 L2”把 `[steps]` 之后的行换成给出的这些行。
  - “改为 `steps = X`”把 `[steps]` 和它之后的行换成这一行。
  - “去掉 K”删除 K 所在的一行或几行。“去掉 `steps`”删除 `[steps]` 和它之后的行。
  - 用例里编了号的各个输入依次写进同一个文件。
- 除非用例另有说明，F04-T14 到 F04-T36 调用 `read_recipe(folder, dish_catalog, "dish")`。

以下约定适用于每个用例：

- 单元格里带引号的字符串是 Python 字面量。所以 `"\u3000"` 是全角空格 U+3000 IDEOGRAPHIC SPACE，`"\x7c"` 是 `|`，`"\\"` 是一个反斜杠，`b"\xff"` 是字节 FF。单引号里的字面量含有双引号，比如 `'a"b'`。单元格里的文件名要么是这样的字面量，要么是代码字体的普通名称，比如 `Rice Bowl.toml`。
- 单元格里的 TOML 项或行，比如 `{ item = "番茄", amount = "\u3000" }`，是 TOML 文字。TOML 把基本字符串里的 `\uXXXX` 和 `\t` 当作转义来读，所以测试既可以写转义，也可以直接写字符本身。
- `EN` 和 `ZH` 代表 `Lang.EN` 和 `Lang.ZH`。`folder` 是用例的 `DataFolder`。
- 写成数字加 `Unit` 成员的数量，比如 `300 G`、`1 JIN` 或 `3 PIECE`，代表 `Quantity(Fraction(300), Unit.G)` 等。`TO_TASTE` 代表适量。在集成用例里，用中文名给出的食材或标签，比如菜心或快手，代表 `catalog.find_ingredient` 或 `catalog.find_tag` 对这个名称给出的对象，用 `is` 比较。
- 一个问题写成它的位置和它的提示，比如 `ingredient 3`：`UNKNOWN_INGREDIENT(name="豆瓣酱")`。位置代表 2.6 的位置表里对应的 `BiText`。所以 `name` 是 `BiText("name", "名称")`，`servings` 是 `BiText("servings", "份数")`，`tags` 是 `BiText("tags", "标签")`，`tag 2` 是 `BiText("tag 2", "标签 2")`，`ingredients` 是 `BiText("ingredients", "食材")`，`ingredient 3` 是 `BiText("ingredient 3", "食材 3")`，`steps` 是 `BiText("steps", "步骤")`，`Chinese step 1` 是 `BiText("Chinese step 1", "中文步骤 1")`，`English step 2` 是 `BiText("English step 2", "英文步骤 2")`。`line 3` 是 `BiText("line 3", "第 3 行")`，与 `read_toml` 给出的相同。“没有位置”指 `place` 为 `None`。
- 提示是设计里各张表中的名称，加上每个占位符的值。2.5 给出 `NOT_A_RECIPE_ID` 和 `RESERVED_RECIPE_ID`，2.6 给出 `recipes` 的提示，3.1 给出文件夹的提示和 `TOML_ENDING_NOT_SMALL`。F03 设计 2.10 给出 `MISSING_KEY`、`NOT_A_LIST`、`NOT_A_TABLE`、`NOT_A_TEXT`、`EMPTY_TEXT`、`ITEM_NOT_A_TEXT`、`EMPTY_ITEM` 和 `UNKNOWN_KEY`，F03 设计 2.3 给出 `read_toml` 的提示，比如 `FILE_MISSING`。英文文字和中文文字就是提示的两个模板填入这些值后的结果。所以 `UNKNOWN_INGREDIENT(name="豆瓣酱")` 是 `Unknown ingredient "豆瓣酱". Add it to the catalog, or use its name in the catalog.` 和 `未知食材“豆瓣酱”。请把它加入目录，或改用目录里的名称。`。模板里写两个花括号的地方，文字里只有一个，比如 `NOT_A_ZH_EN_TABLE` 里的 `{ zh = "...", en = "..." }`。测试把每段文字作为字面量完整写出。它不引用任何提示，因为 `recipes` 的提示和 `datafile` 的文件夹提示都是内部的（设计第 2 节）。
- `UNKNOWN_KEY(key="K")` 的形式和它的值 `keys` 取决于这个键所在的表。在文件顶层，它是 `Unknown key "K". The keys are name, servings, tags, ingredients, and steps.` 和 `未知键“K”。可用的键：name、servings、tags、ingredients 和 steps。`。在一样食材里，它是 `Unknown key "K". The keys are item, amount, and note.` 和 `未知键“K”。可用的键：item、amount 和 note。`。在 `name`、备注和 `steps` 里，它是 `Unknown key "K". The keys are zh and en.` 和 `未知键“K”。可用的键：zh 和 en。`。
- 在 `AMOUNT_NO_UNIT(amount="3", ingredient=tomato)` 里，值 `ingredient` 是这种食材的名称 `tomato.name`。所以英文文字写 `Tomato`，中文文字写 `番茄`。
- 警告在位置后面标上“（警告）”，比如 `steps`（警告）：`NO_EN_STEPS`。其他每个问题都是错误。测试检查每个问题的严重程度：`Severity.WARNING` 或 `Severity.ERROR`。
- 每个问题的文件是它的读取函数所读的文件。在 F04-T14 到 F04-T36 里，它是 `Path("recipes", "dish.toml")`。其他用例给出文件，比如 `recipes/pancakes.TOML`，它代表 `Path("recipes", "pancakes.TOML")`。测试把 `str(problem.file)` 和这个路径的 `str` 比较。在 Windows 上，`Path` 比较路径时不区分大小写，所以那里 `Path("recipes", "pancakes.TOML") == Path("recipes", "pancakes.toml")` 为真。比较 `Path` 值检查不出名称的大小写。
- 测试按顺序比较整个问题元组，比较每个问题的严重程度、文件、位置、`text(EN)` 和 `text(ZH)`。“没有问题”指空元组。“没有菜谱”指菜谱为 `None`。
- Python 限制它读写的 `int` 的位数。F04-T19、F04-T34、F04-T41、F04-T56 和 F04-T58 使用 `tests/conftest.py` 的夹具 `default_int_limit`。它把上限设为默认的 4,300 位，结束后恢复原来的上限，与 F03 的用例相同。所以 `PYTHONINTMAXSTRDIGITS` 改变不了它们的结果。
- 对文件夹 `path`“拒绝列出”指以下做法：
  - 在 Linux 上，测试用 `os.chmod` 把 `path` 的权限设为 `0o100`，结束后改回 `0o755`。这个文件夹保留打开其中文件所需的搜索权限，失去列出它所需的读权限。root 用户仍然能列出它，而 CI 以用户 `runner` 运行。
  - 在 Windows 上，测试用 `_winapi.CreateFile(str(path), 0x80000000, 0, 0, _winapi.OPEN_EXISTING, 0x02000000, 0)` 打开 `path` 并保持打开，结束后用 `_winapi.CloseHandle` 关闭句柄。这个调用以共享模式 0 和 `FILE_FLAG_BACKUP_SEMANTICS` 请求 `GENERIC_READ`。这时列出 `path` 会因共享冲突失败，Python 把它作为 `PermissionError` 抛出，而文件夹里的文件仍然能打开。在 Troy 的电脑上，Python 3.13.18 和 3.14.3 都是这样。
  - 在两个系统上，测试都先检查 `os.listdir(path)` 抛出 `PermissionError`。
