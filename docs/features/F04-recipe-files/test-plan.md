# F04 Recipe files: test plan

## 1. Feature

- ID and name: F04 Recipe files
- Design: [design.md](design.md), version 1.0

## 2. Cases

The tests call the interfaces of `recipe_menu.recipes`, and the two new interfaces of `recipe_menu.datafile`: `list_toml_files` and `Report.warn`. F04 has no command, so the plan has no functional cases. A unit case calls one interface with inputs that it builds. An integration case joins several interfaces, reads the example data folder, or checks the lines of a prototype or a v0.1 scenario at the readers. Each case names the section of the design that it comes from, such as (2.6).

The Architect's review of the design (design section 4, rounds 1 and 2) names cases that the design's examples do not show:

- F04-T29 and F04-T30 hold the steps of the Architect's model: `zh = ""`, `zh = " "`, and `zh = 3` give `NOT_A_LIST` at `steps`, `zh = []` gives the warning `NO_ZH_STEPS`, `zh = [" "]` gives `EMPTY_ITEM` at `Chinese step 1`, and `zh = ""` with `en = []` gives no `NO_STEPS`.
- F04-T15 and F04-T27 hold a blank text in a name and in a note, which stays a missing language.
- F04-T18, F04-T19, and F04-T41 hold the numbers of up to 15 digits that a message shows, and the hexadecimal integer of 5,000 digits that no message shows.
- F04-T50 and F04-T51 hold the sort key of `TOML_ENDING_NOT_SMALL`, which the Interface Designer settled in section 5: the whole entry name, compared as a `str`.
- F04-T12 and F04-T51 run on Linux only, because of how Windows treats device names and the case of names.
- F04-T58 holds random recipe files, as F03-T86 holds random catalogs.

The design's 9 examples hold 13 `# raises` lines. F04-T01, F04-T03, F04-T04, F04-T05, F04-T42, and F04-T48 hold them all.

Each case calls code that the mock leaves out: `is_recipe_id`, `list_recipe_ids`, `read_recipe`, `read_recipes`, `list_toml_files`, `Report.warn`, `Steps.get`, `Steps.exact`, or the checks in the constructors of `RecipeIngredient`, `Steps`, and `Recipe`. So each test fails against the mock (R09). The mock keeps the bodies of `Report.add`, `read_list`, `read_table`, `read_text`, and `report_unknown_keys`, which move from `catalog` (design 3.2), so that F03's tests still pass. A case that tested them alone would pass against the mock, so no case does. F04-T55 calls them only around `warn`. Section 4 lists what the mock declares in full.

Every case runs on Linux and on Windows, except F04-T12 and F04-T51. These two run on Linux only and are skipped on Windows, and each says why. CI runs on Linux, so CI runs and checks them. On Troy's PC, the flow's check of skipped tests lists them as checked by CI. F04-T36, F04-T52, and F04-T53 cause their `OSError` in a different way on each system, and F04-T13 and F04-T52 get a different `OSError` on each system. Each of them says how.

These rules hold for the test data:

- `tests/data/example/` holds the example data folder of `docs/prototypes/example-data.md`, with its 7 recipes (architecture 10). The fixture `example_folder` of `tests/conftest.py` copies it into `tmp_path` with LF line ends and gives a `DataFolder` on the copy. The fixture `folder` gives a `DataFolder` on the empty `tmp_path`. So no test changes the repository or touches `~/recipe-menu`. "The example folder" in a case means the copy. "The example catalog" is the catalog that `read_catalog` gives for the example folder, with no problems (F03-T48).
- F04-T09, F04-T37 to F04-T44, F04-T47, F04-T48, and F04-T57 use the example folder. Every other case writes small files of its own into the `DataFolder` of `folder`, or into a `DataFolder` that it names on a part of `tmp_path`.
- The tests write every file as bytes, or with `write_text(text, encoding="utf-8", newline="\n")`, and create its folders first. So a file has the same bytes on both systems.

These values and files hold in every case:

- Some values come from the design's examples, and the tests build them as the design does. `produce`, `tomato`, and `wedges` come from 2.1. `chinese` and `both` come from 2.2. `choy_sum`, `quick`, `name`, `lines`, and `steps` come from 2.3.
- `dish_catalog` is `Catalog((produce, eggs), (tomato, egg, scallion), (quick, home))`, with `eggs = Category("eggs", BiText("Eggs, dairy, and tofu", "蛋奶豆制品"))`, `egg = Ingredient(BiText("Egg", "鸡蛋"), eggs, Unit.PIECE)`, `scallion = Ingredient(BiText("Scallion", "葱"), produce, Unit.STALK)`, and `home = Tag(BiText("home-style", "家常"))`. So `tomato` has no default unit.
- "The base recipe" is this file, written as `folder.recipe_file("dish")`:

```text
name = { zh = "番茄炒蛋", en = "Tomato and egg stir-fry" }
servings = 2
tags = ["快手"]
ingredients = [
  { item = "番茄", amount = "300 g" },
]

[steps]
zh = ["番茄切块。"]
en = ["Cut the tomatoes."]
```

- `dish` is the recipe of the base recipe: `Recipe("dish", BiText("Tomato and egg stir-fry", "番茄炒蛋"), 2, (quick,), (RecipeIngredient(tomato, Quantity(Fraction(300), Unit.G)),), Steps(("Cut the tomatoes.",), ("番茄切块。",)))`. "`dish` with `f=v`" means `dataclasses.replace(dish, f=v)`.
- A case changes the base recipe in these ways:
  - "With `name = X`" replaces the line of that key. The same holds for `servings` and `tags`.
  - "With ingredients A and B" puts A and B between `ingredients = [` and `]`, each on its own line, indented by two spaces and followed by a comma. "With the ingredient A" puts A there alone.
  - "With `ingredients = X`" replaces the three lines of the list with that one line.
  - "With steps L1 and L2" replaces the lines after `[steps]` with the lines given.
  - "With `steps = X`" replaces `[steps]` and the lines after it with that one line.
  - "Without K" deletes the line or the lines of K. "Without `steps`" deletes `[steps]` and the lines after it.
  - The numbered inputs of a case are written in turn into the same file.
- F04-T14 to F04-T36 call `read_recipe(folder, dish_catalog, "dish")`, unless the case says otherwise.

These conventions hold in every case:

- A quoted string in a cell is a Python literal. So `"\u3000"` is U+3000 IDEOGRAPHIC SPACE, `"\x7c"` is `|`, `"\\"` is one backslash, and `b"\xff"` is the byte FF. A literal in single quotes holds a double quote, such as `'a"b'`. A file name in a cell is such a literal, or a plain name in code font, such as `Rice Bowl.toml`.
- A TOML item or line in a cell, such as `{ item = "番茄", amount = "\u3000" }`, is TOML text. TOML reads `\uXXXX` and `\t` in a basic string as escapes, so a test may write the escape or the character itself.
- `EN` and `ZH` stand for `Lang.EN` and `Lang.ZH`. `folder` is the `DataFolder` of the case.
- A quantity written as a number and a `Unit` member, such as `300 G`, `1 JIN`, or `3 PIECE`, stands for `Quantity(Fraction(300), Unit.G)` and so on. `TO_TASTE` stands for to taste. In the integration cases, an ingredient or a tag given by its Chinese name, such as 菜心 or 快手, stands for the object that `catalog.find_ingredient` or `catalog.find_tag` gives for that name, compared by `is`.
- A problem is written as its place and its message, such as `ingredient 3`: `UNKNOWN_INGREDIENT(name="豆瓣酱")`. The place stands for its `BiText` in the table of places of 2.6. So `name` is `BiText("name", "名称")`, `servings` is `BiText("servings", "份数")`, `tags` is `BiText("tags", "标签")`, `tag 2` is `BiText("tag 2", "标签 2")`, `ingredients` is `BiText("ingredients", "食材")`, `ingredient 3` is `BiText("ingredient 3", "食材 3")`, `steps` is `BiText("steps", "步骤")`, `Chinese step 1` is `BiText("Chinese step 1", "中文步骤 1")`, and `English step 2` is `BiText("English step 2", "英文步骤 2")`. `line 3` is `BiText("line 3", "第 3 行")`, as `read_toml` gives it. "No place" means that `place` is `None`.
- The message is a name from the tables of the design, with the value of each placeholder. 2.5 gives `NOT_A_RECIPE_ID` and `RESERVED_RECIPE_ID`, 2.6 gives the messages of `recipes`, and 3.1 gives the folder messages and `TOML_ENDING_NOT_SMALL`. F03 design 2.10 gives `MISSING_KEY`, `NOT_A_LIST`, `NOT_A_TABLE`, `NOT_A_TEXT`, `EMPTY_TEXT`, `ITEM_NOT_A_TEXT`, `EMPTY_ITEM`, and `UNKNOWN_KEY`, and F03 design 2.3 gives the messages of `read_toml`, such as `FILE_MISSING`. The English and Chinese texts are the message's two templates with the values filled in. So `UNKNOWN_INGREDIENT(name="豆瓣酱")` is `Unknown ingredient "豆瓣酱". Add it to the catalog, or use its name in the catalog.` and `未知食材“豆瓣酱”。请把它加入目录，或改用目录里的名称。`. A text has one brace where a template writes two, such as `{ zh = "...", en = "..." }` in `NOT_A_ZH_EN_TABLE`. The test writes each text out in full as a literal. It imports no message, because the messages of `recipes` and the folder messages of `datafile` are internal (design section 2).
- `UNKNOWN_KEY(key="K")` takes its form and its value `keys` from the table that holds the key. At the top of the file, it is `Unknown key "K". The keys are name, servings, tags, ingredients, and steps.` and `未知键“K”。可用的键：name、servings、tags、ingredients 和 steps。`. In an ingredient, it is `Unknown key "K". The keys are item, amount, and note.` and `未知键“K”。可用的键：item、amount 和 note。`. In `name`, in a note, and in `steps`, it is `Unknown key "K". The keys are zh and en.` and `未知键“K”。可用的键：zh 和 en。`.
- In `AMOUNT_NO_UNIT(amount="3", ingredient=tomato)`, the value `ingredient` is the ingredient's name, `tomato.name`. So the English text names `Tomato`, and the Chinese text names `番茄`.
- A warning is marked "(warning)" after its place, such as `steps` (warning): `NO_EN_STEPS`. Every other problem is an error. The test checks each problem's severity, `Severity.WARNING` or `Severity.ERROR`.
- Each problem has the file of its reader. In F04-T14 to F04-T36, it is `Path("recipes", "dish.toml")`. Other cases give the file, such as `recipes/pancakes.TOML`, which stands for `Path("recipes", "pancakes.TOML")`. The test compares `str(problem.file)` with `str` of that path. On Windows, `Path` compares paths without case, so `Path("recipes", "pancakes.TOML") == Path("recipes", "pancakes.toml")` is true there. Comparing `Path` values would not check the case of a name.
- The test compares the whole tuple of problems, in order, by severity, file, place, `text(EN)`, and `text(ZH)`. "No problems" means the empty tuple. "No recipe" means that the recipe is `None`.
- Python limits the digits of an `int` that it reads or writes. F04-T19, F04-T34, F04-T41, F04-T56, and F04-T58 use the fixture `default_int_limit` of `tests/conftest.py`. It sets the limit to its default of 4,300 digits and puts the old limit back, as in F03's cases. So `PYTHONINTMAXSTRDIGITS` cannot change their results.
- "Listing is denied" for a folder `path` means this:
  - On Linux, the test sets the mode of `path` to `0o100` with `os.chmod`, and puts `0o755` back afterwards. The folder keeps the search permission that opening a file in it needs, and loses the read permission that listing it needs. The root user could still list it, and CI runs as the user `runner`.
  - On Windows, the test holds `path` open with `_winapi.CreateFile(str(path), 0x80000000, 0, 0, _winapi.OPEN_EXISTING, 0x02000000, 0)`, and closes the handle with `_winapi.CloseHandle` afterwards. The call asks for `GENERIC_READ` with the share mode 0 and `FILE_FLAG_BACKUP_SEMANTICS`. Listing `path` then fails with a sharing violation, which Python raises as `PermissionError`, and a file in the folder still opens. Python 3.13.18 and 3.14.3 behave so on Troy's PC.
  - On each system, the test first checks that `os.listdir(path)` raises `PermissionError`.
