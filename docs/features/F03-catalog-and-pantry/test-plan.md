# F03 Catalog and pantry: test plan

## 1. Feature

- ID and name: F03 Catalog and pantry
- Design: [design.md](design.md), version 1.0

## 2. Cases

The tests call the interfaces of `recipe_menu.datafile` and `recipe_menu.catalog`. F03 has no command, so the plan has no functional cases. A unit case calls one interface with inputs that it builds. An integration case joins several F03 interfaces, reads the example data folder, or checks the lines of a prototype or a v0.1 scenario at the readers. Each case names the section of the design that it comes from, such as (2.8).

The Architect's review of the design (design section 4, round 2) names six cases that the design's examples do not show. F03-T67 holds the category whose key and Chinese name both repeat an earlier one. F03-T68 holds the three categories with one English name, and the category that keeps its ingredients although its name is shared. F03-T19 holds the bytes `EF BB BF 61 0A FF`, F03-T35 the nesting, and F03-T86 the random catalogs.

Each case calls code that the mock leaves out: a property, a method, or a function body, or the checks in the constructors of the values. So each test fails against the mock (R09). F02's `Message.render` is already implemented, so no case checks an F03 message with `render` alone. Each one goes through `Problem.text` or a reader. Section 4 lists what the mock declares in full.

Every case runs on Linux and on Windows. F03-T17 and F03-T18 cause their `OSError` in a different way on each system, and F03-T15 gets a different `OSError` on each system. Each of them says how.

These rules hold for the test data:

- `tests/data/example/` holds the whole data folder of `docs/prototypes/example-data.md` (architecture 10). It does not exist yet. The Test Engineer creates it in F03's tests PR. `settings.toml`, `catalog.toml`, `pantry.toml`, and `recipes/tomato-egg.toml` are byte for byte as the prototype shows them, in UTF-8 without a byte order mark and with LF line ends. The six other recipes follow the prototype's table in the layout of `tomato-egg.toml`, and `menus/2026-W47.toml` is the prototype's menu.
- A fixture in `tests/conftest.py`, such as `example_folder`, copies that folder into `tmp_path` for each test and gives a `DataFolder` on the copy. So no test changes the repository or touches `~/recipe-menu`. "The example folder" in a case means this copy.
- F03's cases read only the settings, the catalog, the pantry, and `recipes/tomato-egg.toml` of the example folder. F04 and F06 check the other files.
- F03-T12, F03-T13, F03-T48, F03-T50, F03-T72, F03-T73, and F03-T79 to F03-T85 use the example folder. Every other case writes a small file of its own into a `DataFolder` on an empty `tmp_path`.
- The tests write every file as bytes, or with `write_text(text, encoding="utf-8", newline="\n")`. So a file has the same bytes on both systems, and only a case that asks for CRLF line ends gets them.
- F03-T21 to F03-T35 write their text into `folder.settings`, unless a case names another file. Each text gives one `Problem` whose file is the file written, such as `Path("settings.toml")`, unless the case expects a table.

These conventions hold in every case:

- A quoted string in a cell is a Python literal. So `"\u3000"` is U+3000 IDEOGRAPHIC SPACE, `"\n"` is a line break, `"\\"` is one backslash, and `b"\xff"` is the byte FF. A literal in single quotes holds a double quote, such as `'zh = "番茄'`.
- A message text is the whole code span, with no quotes around it, such as `The key "tags" is missing.` or `缺少键“tags”。`. It is the text itself, as the design writes it. In a message text, `\uXXXX` stands for the one character U+XXXX.
- A TOML item in a cell, such as `{ zh = "\u3000葱", en = "Scallion" }`, is TOML text. TOML reads `\uXXXX` and `\t` in it as escapes, so a test may write the escape or the character itself.
- `EN` and `ZH` stand for `Lang.EN` and `Lang.ZH`. `folder` is the `DataFolder` of the case.
- Some values come from the design's examples, and the tests build them as the design does. `UNKNOWN_TAG`, `NO_ENGLISH_STEPS`, `rice`, and `tags` come from 2.2. `produce` and `quick` come from 2.4. `meat`, `tomato`, `pork`, `greens`, `fruit`, and `tomato_again` come from 2.5. `kale` and `scallion` come from 2.6, so `scallion` has no unit. `seasonings`, `salt`, and `sugar` come from 2.7.
- `find_catalog` is `Catalog((produce,), (kale, scallion, choy_sum, jalapeno, puree, xo_sauce, tomato), (quick,))`. Its new ingredients are `choy_sum = Ingredient(BiText("Choy sum", "菜心"), produce)`, `jalapeno = Ingredient(BiText("Jalape\u00f1o", "墨西哥辣椒"), produce)`, `puree = Ingredient(BiText("Tomato pur\u00e9e", "番茄泥"), produce)`, and `xo_sauce = Ingredient(BiText("XO sauce", "XO酱"), produce)`.
- `pantry_catalog` is `Catalog((seasonings,), (salt, sugar), ())`.
- A catalog given by its items has the layout of design 2.8: `categories = [`, each item on its own line followed by a comma, and `]`, then the same for `ingredients` and for `tags`. A list that the case does not give is empty, such as `tags = []`. `produce_item` stands for `{ key = "produce", zh = "蔬菜水果", en = "Vegetables and fruit" }`, `meat_item` for `{ key = "meat", zh = "肉类水产", en = "Meat and seafood" }`, `tomato_item` for `{ zh = "番茄", en = "Tomato", category = "produce" }`, and `quick_item` for `{ zh = "快手", en = "quick" }`.
- "The example catalog with ingredient 23 X" is the example's `catalog.toml` with the item X added at the end of `ingredients`. "With ingredient 7 changed to X" replaces the line of that item. A pantry "with item 3 changed to X" replaces the third item of the list.
- A problem is written as its place, then its English text and its Chinese text, such as `ingredient 3`: `Unknown unit "cups".` and `未知单位“cups”。`. A place stands for its `BiText` in the tables of places of design 2.3, 2.8, and 2.9. So `ingredient 3` is `BiText("ingredient 3", "食材 3")`, `item 3` is `BiText("item 3", "第 3 项")`, `line 2` is `BiText("line 2", "第 2 行")`, `categories` is `BiText("categories", "分类")`, and `pantry` is `BiText("pantry", "常备清单")`. "No place" means that `place` is `None`.
- The test compares the whole tuple of problems, in order, by place, `text(EN)`, and `text(ZH)`. It also checks that each problem has `Severity.ERROR` and the file of its reader: `Path("catalog.toml")` for `read_catalog`, `Path("pantry.toml")` for `read_pantry`, and `folder.relative(path)` for `read_toml`. "No problems" means the empty tuple.
- Kept items are listed in order: the categories by key, and the ingredients and the tags by English name, such as "kept ingredients: Tomato, Scallion".
- Python limits the digits of an `int` that it reads or writes. F03-T09 and F03-T34 use the fixture `default_int_limit` of `tests/conftest.py`, which sets the limit to its default of 4,300 digits and puts the old limit back, as F01's and F02's cases do. So `PYTHONINTMAXSTRDIGITS` cannot change their results.
