# F03 目录和常备清单：测试方案

## 1. 功能

- 编号和名称：F03 目录和常备清单
- 设计：[design.zh-CN.md](design.zh-CN.md)，版本 1.0

## 2. 用例

测试调用 `recipe_menu.datafile` 和 `recipe_menu.catalog` 的接口。F03 没有命令，所以方案里没有功能用例。单元用例用它自己构造的输入调用一个接口。集成用例把几个 F03 接口连起来、读取示例数据文件夹，或者在读取函数这一层检查原型或 v0.1 场景里的行。每个用例在括号里注明它来自设计的哪一节，比如（2.8）。

架构师对设计的审查（设计第 4 节，第 2 轮）列出了设计的示例没有展示的六个用例。F03-T67 是键和中文名都与更早的分类重复的分类。F03-T68 是三个英文名相同的分类，以及名称与别的分类相同、但仍保留食材的分类。F03-T19 是字节 `EF BB BF 61 0A FF`，F03-T35 是嵌套，F03-T86 是随机目录。

每个用例都调用 mock 里没有的代码：属性、方法或函数的函数体，或者值的构造函数里的检查。所以每个测试对着 mock 都失败（R09）。F02 的 `Message.render` 已经实现，所以没有用例只用 `render` 检查 F03 的提示。每条提示都通过 `Problem.text` 或读取函数检查。第 4 节列出 mock 完整声明的内容。

每个用例在 Linux 和 Windows 上都能运行。F03-T17 和 F03-T18 在两个系统上用不同的办法引发 `OSError`，F03-T15 在两个系统上得到不同的 `OSError`。这几个用例都说明了做法。

测试数据遵守这些规则：

- `tests/data/example/` 存放 `docs/prototypes/example-data.md` 里的整个数据文件夹（架构 10）。它现在还不存在，由测试工程师在 F03 的测试 PR 里创建。`settings.toml`、`catalog.toml`、`pantry.toml` 和 `recipes/tomato-egg.toml` 与原型逐字节相同，用不带字节顺序标记的 UTF-8 和 LF 换行。另外六个菜谱按原型里的表格写成，格式与 `tomato-egg.toml` 相同，`menus/2026-W47.toml` 就是原型里的周菜单。
- `tests/conftest.py` 里的一个夹具，比如 `example_folder`，为每个测试把这个文件夹复制到 `tmp_path`，并给出副本上的 `DataFolder`。所以没有测试改动仓库或碰到 `~/recipe-menu`。用例里说的“示例文件夹”就是这个副本。
- F03 的用例只读取示例文件夹里的设置、目录、常备清单和 `recipes/tomato-egg.toml`。其他文件由 F04 和 F06 检查。
- F03-T12、F03-T13、F03-T48、F03-T50、F03-T72、F03-T73 以及 F03-T79 到 F03-T85 使用示例文件夹。其他每个用例都把自己的小文件写进空的 `tmp_path` 上的 `DataFolder`。
- 测试写每个文件时，要么写字节，要么用 `write_text(text, encoding="utf-8", newline="\n")`。所以同一个文件在两个系统上的字节相同，只有要求 CRLF 换行的用例才得到 CRLF。
- F03-T21 到 F03-T35 把文字写进 `folder.settings`，除非用例指定了别的文件。除非用例预期得到一个表，每段文字都给出一个 `Problem`，它的文件就是写入的那个文件，比如 `Path("settings.toml")`。

以下约定适用于每个用例：

- 单元格里带引号的字符串是 Python 字面量。所以 `"\u3000"` 是全角空格 U+3000 IDEOGRAPHIC SPACE，`"\n"` 是换行符，`"\\"` 是一个反斜杠，`b"\xff"` 是字节 FF。单引号里的字面量含有双引号，比如 `'zh = "番茄'`。
- 提示文字是整个代码片段，外面没有引号，比如 `The key "tags" is missing.` 或 `缺少键“tags”。`。它就是文字本身，与设计里的写法相同。在提示文字里，`\uXXXX` 代表 U+XXXX 这一个字符。
- 单元格里的 TOML 项，比如 `{ zh = "\u3000葱", en = "Scallion" }`，是 TOML 文字。TOML 把其中的 `\uXXXX` 和 `\t` 当作转义来读，所以测试既可以写转义，也可以直接写字符本身。
- `EN` 和 `ZH` 代表 `Lang.EN` 和 `Lang.ZH`。`folder` 是用例的 `DataFolder`。
- 有些值来自设计里的示例，测试照设计的写法构造它们。`UNKNOWN_TAG`、`NO_ENGLISH_STEPS`、`rice` 和 `tags` 来自 2.2。`produce` 和 `quick` 来自 2.4。`meat`、`tomato`、`pork`、`greens`、`fruit` 和 `tomato_again` 来自 2.5。`kale` 和 `scallion` 来自 2.6，所以 `scallion` 没有单位。`seasonings`、`salt` 和 `sugar` 来自 2.7。
- `find_catalog` 是 `Catalog((produce,), (kale, scallion, choy_sum, jalapeno, puree, xo_sauce, tomato), (quick,))`。其中新的食材是 `choy_sum = Ingredient(BiText("Choy sum", "菜心"), produce)`、`jalapeno = Ingredient(BiText("Jalape\u00f1o", "墨西哥辣椒"), produce)`、`puree = Ingredient(BiText("Tomato pur\u00e9e", "番茄泥"), produce)` 和 `xo_sauce = Ingredient(BiText("XO sauce", "XO酱"), produce)`。
- `pantry_catalog` 是 `Catalog((seasonings,), (salt, sugar), ())`。
- 用项给出的目录采用设计 2.8 的格式：`categories = [`，每一项单独一行、后面跟一个逗号，然后是 `]`；`ingredients` 和 `tags` 也一样。用例没有给出的列表为空，比如 `tags = []`。`produce_item` 代表 `{ key = "produce", zh = "蔬菜水果", en = "Vegetables and fruit" }`，`meat_item` 代表 `{ key = "meat", zh = "肉类水产", en = "Meat and seafood" }`，`tomato_item` 代表 `{ zh = "番茄", en = "Tomato", category = "produce" }`，`quick_item` 代表 `{ zh = "快手", en = "quick" }`。
- “示例目录加上食材 23 X”指示例的 `catalog.toml` 在 `ingredients` 末尾加上 X 这一项。“把食材 7 改为 X”指替换那一项所在的行。常备清单“把第 3 项改为 X”指替换列表的第三项。
- 一个问题写成它的位置，然后是它的英文文字和中文文字，比如 `ingredient 3`：`Unknown unit "cups".` 和 `未知单位“cups”。`。位置代表设计 2.3、2.8 和 2.9 的位置表里对应的 `BiText`。所以 `ingredient 3` 是 `BiText("ingredient 3", "食材 3")`，`item 3` 是 `BiText("item 3", "第 3 项")`，`line 2` 是 `BiText("line 2", "第 2 行")`，`categories` 是 `BiText("categories", "分类")`，`pantry` 是 `BiText("pantry", "常备清单")`。“没有位置”指 `place` 为 `None`。
- 测试按顺序比较整个问题元组，比较每个问题的位置、`text(EN)` 和 `text(ZH)`。它还检查每个问题的严重程度为 `Severity.ERROR`，文件为它的读取函数的文件：`read_catalog` 是 `Path("catalog.toml")`，`read_pantry` 是 `Path("pantry.toml")`，`read_toml` 是 `folder.relative(path)`。“没有问题”指空元组。
- 保留的项按顺序列出：分类用键，食材和标签用英文名，比如“保留的食材：Tomato、Scallion”。
- Python 限制它读写的 `int` 的位数。F03-T09 和 F03-T34 使用 `tests/conftest.py` 的夹具 `default_int_limit`，它把上限设为默认的 4,300 位，结束后恢复原来的上限，与 F01 和 F02 的用例相同。所以 `PYTHONINTMAXSTRDIGITS` 改变不了它们的结果。
