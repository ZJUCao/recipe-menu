# F02 双语终端输出：测试方案

## 1. 功能

- 编号和名称：F02 双语终端输出
- 设计：[design.zh-CN.md](design.zh-CN.md)，版本 1.0

## 2. 用例

测试直接调用 `recipe_menu.lang` 和 `recipe_menu.text` 的接口。它们不读任何文件，也没有测试写入测试运行器的 `sys.stdout` 或 `sys.stderr`，或者写入控制台。F02 没有命令，所以方案里没有功能用例。集成用例把几个 F02 接口连起来，得到原型里的各行。F02-T70 在一个 Python 子进程里运行 `use_utf8`。每个用例在括号里注明它来自设计的哪一节，比如（2.6，规则 2）。

每个用例都依赖 mock 里没有的代码：方法或函数的函数体，或者 `BiText`、`Message` 和 `Plural` 的检查。所以每个测试对着 mock 都失败（R09）。第 4 节列出 mock 完整声明的内容。

每个用例在 Linux 和 Windows 上都能运行。没有用例依赖系统的换行符、路径分隔符或控制台。表格单元格里的路径，比如 `"recipes\\tomato-egg.toml"`，只是普通字符串。

以下约定适用于每个用例：

- 引号里的字符串是 Python 字面量。所以 `"\u3000"` 是全角空格 U+3000，`"\n"` 是换行符，`"\\"` 是一个反斜杠。单引号里的字面量，比如 `'Unknown recipe "rice".'`，含有双引号。
- `EN` 和 `ZH` 代表 `Lang.EN` 和 `Lang.ZH`。`BiText("a", "b")` 的英文是 `"a"`，中文是 `"b"`。`BiText(zh="素")` 没有英文。
- 有些名称是设计里示例的值，测试照设计的写法构造它们。`UNKNOWN_RECIPE`、`SERVINGS`、`tags` 和 `NO_OTHER` 来自 2.3。`WITH_TAG`、`quick` 和 `ONE_ERROR` 来自 2.4。`meals`、`QUOTED`、`SETTINGS`、`CATALOG`、`PANTRY`、`RECIPES`、`WEEK_MENUS` 和 `CHECKED` 来自 2.6。`tags` 始终是 2.3 里的 `BiText("quick, home-style", "快手、家常")`。
- `braced` 代表 `"{" * 2 + "name" + "}" * 2`：用双写花括号括起来的单词 `name`，模板把它显示为文字 `{name}`。方案把它写成表达式，因为 troy-check 会把文档里用双写花括号括起来的单词当成模板标记（R20）。测试可以直接写字面量。
- `MealKind.DINNER`、`Size.ONE` 和 `Colour.RED` 是测试自己定义的枚举的成员。`MealKind` 是值为 `"dinner"` 的 `StrEnum`，代替架构 5.2 里的 `Meal`。`Size` 是值为 1 的 `IntEnum`，`Colour` 是值为 `"red"` 的 `Enum`。
- 用例自己定义的提示，比如 F02-T38 的 `MATCH`，代表后续功能的一条提示。它的中文模板是测试自己写的。除非用例给出别的预期文字，它只比较原型或 v0.1 场景里出现的行。
- 用例说到原型里的行时，把整个结果和这些行逐字符、按顺序比较。测试把这些行写成从原型复制来的字符串字面量。每个单元格也是字面量，除非用例用另一个 F02 接口构造它。
- Python 限制它写出的 `int` 的位数。F02-T24 用 `sys.set_int_max_str_digits(4300)` 把这个上限设为默认的 4,300 位，测试结束后恢复原来的上限，与 F01 的用例相同。所以 `PYTHONINTMAXSTRDIGITS` 改变不了它的结果。
- `use_utf8` 会改变它得到的流，所以没有用例把测试运行器的 `sys.stdout` 或 `sys.stderr` 传给它。F02-T67 和 F02-T68 给它一个包在 `io.BytesIO` 外面的 `io.TextIOWrapper`。F02-T69 给它字符串流，F02-T70 给它子进程的标准流。
