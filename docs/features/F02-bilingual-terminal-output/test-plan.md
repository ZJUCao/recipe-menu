# F02 Bilingual terminal output: test plan

## 1. Feature

- ID and name: F02 Bilingual terminal output
- Design: [design.md](design.md), version 1.0

## 2. Cases

The tests call the interfaces of `recipe_menu.lang` and `recipe_menu.text` directly. They read no files, and no test writes to the test runner's `sys.stdout` or `sys.stderr` or to a console. F02 has no command, so the plan has no functional cases. The integration cases join several F02 interfaces into lines of the prototypes, and F02-T70 runs `use_utf8` in a child Python process. Each case names the section of the design that it comes from, such as (2.6, rule 2).

Each case depends on code that the mock leaves out: a method or function body, or the checks in `BiText`, `Message`, and `Plural`. So each test fails against the mock (R09). Section 4 lists what the mock declares in full.

Every case runs on Linux and on Windows. No case depends on the system's line ends, path separator, or console. A path in a table cell, such as `"recipes\\tomato-egg.toml"`, is a plain string.

These conventions hold in every case:

- A string in quotes is a Python literal. So `"\u3000"` is the ideographic space U+3000, `"\n"` is a line break, and `"\\"` is one backslash. A literal in single quotes, such as `'Unknown recipe "rice".'`, holds a double quote.
- `EN` and `ZH` stand for `Lang.EN` and `Lang.ZH`. `BiText("a", "b")` has the English text `"a"` and the Chinese text `"b"`, and `BiText(zh="素")` has no English.
- Some names are the values of the design's examples, and the tests build them as the design does. `UNKNOWN_RECIPE`, `SERVINGS`, `tags`, and `NO_OTHER` come from 2.3. `WITH_TAG`, `quick`, and `ONE_ERROR` come from 2.4. `meals`, `QUOTED`, `SETTINGS`, `CATALOG`, `PANTRY`, `RECIPES`, `WEEK_MENUS`, and `CHECKED` come from 2.6. `tags` is always the `BiText("quick, home-style", "快手、家常")` of 2.3.
- `braced` stands for `"{" * 2 + "name" + "}" * 2`: the word `name` in doubled braces, which a template shows as the text `{name}`. The plan writes it as an expression because troy-check reads a word in doubled braces in a document as a template marker (R20). The tests may write the literal.
- `MealKind.DINNER`, `Size.ONE`, and `Colour.RED` are members of enums that the tests define. `MealKind` is a `StrEnum` with the value `"dinner"`, in place of the `Meal` of architecture 5.2. `Size` is an `IntEnum` with the value 1, and `Colour` is an `Enum` with the value `"red"`.
- A message that a case defines, such as `MATCH` in F02-T38, stands for a message of a later feature. Its Chinese template is the test's own. The case compares only the lines that a prototype or a v0.1 scenario shows, unless it gives another expected text.
- A case that names the lines of a prototype compares the whole result with those lines, character for character and in order. The test holds them as string literals copied from the prototype. Each cell is a literal too, except where the case builds the cell with another F02 interface.
- Python limits the digits of an `int` that it writes. F02-T24 sets that limit to its default of 4,300 digits with `sys.set_int_max_str_digits(4300)`, and puts the old limit back afterwards, as F01's cases do. So `PYTHONINTMAXSTRDIGITS` cannot change its results.
- `use_utf8` changes the stream that it gets, so no case passes it the test runner's `sys.stdout` or `sys.stderr`. F02-T67 and F02-T68 give it an `io.TextIOWrapper` over an `io.BytesIO`. F02-T69 gives it string streams, and F02-T70 gives it the standard streams of a child process.

## 4. Not tested

| What | Why |
| --- | --- |
| The fields, the field defaults, the equality, the hash, and the immutability of `BiText`, `Message`, and `Plural`. | `@dataclass(frozen=True, slots=True)` in the design's signatures gives them, and the mock declares it, so their own tests would pass against the mock (R09). Most cases compare whole `BiText` values with `==`, and F02-T25 checks the messages that `pick` gives by identity. |
| `MessageValue`. | It is a type alias, which the mock declares in full. mypy in strict mode checks its use. F02-T22 checks the values that `render` rejects at run time. |
| The templates of `RUN_CHECK`, `RUN_HELP_FOR_OPTIONS`, and `RUN_HELP_FOR_COMMANDS` read as fields, such as `RUN_CHECK.en`. | The mock declares the three constants with their text, so a test of the fields would pass against the mock (R09). F02-T28 checks the same text through `render`. |
| The names that `__all__` lists in `recipe_menu.lang` and `recipe_menu.text`. | The mock declares `__all__` in full, so a test of it would pass against the mock (R09). Every test imports its names from these two modules, and mypy in strict mode checks the exports once later features import them (architecture 8). |
| `lang` imports nothing from the package, and `text` imports only `lang`. | R07. The dependency checker in CI compares each import with the table in architecture 3. |
| No interface prints, reads a file or the environment, or keeps state. | ruff's `T20` rules ban `print()`, architecture 8 gives the outside world to `cli` alone, and code review checks module-level state. A test could show only that the calls it makes print nothing. |
| Doc comments are in English only. | R05. troy-check rejects Chinese characters in doc comments. |
| `format_table` with a cell that is not a `str`, such as a `StrEnum` member. | The design does not check the type of a cell, so there is no behavior to test. The Architect's review notes that a Chinese table compared with its prototype catches a `StrEnum` cell. So F02-T58 to F02-T61 and F02-T63 to F02-T66 compare every Chinese table of the prototypes line by line, and the tests of F05 to F13 do the same for the tables that their commands print. |
| The time that `format_table` and `display_width` take. | No F02 interface has a performance target (R14). v0.1-S27 to v0.1-S32 time the commands of PT01, which print through `format_table`. |
| `render` under a limit on `int` digits other than the default of 4,300, such as one that `PYTHONINTMAXSTRDIGITS` sets. | Design 2.3 states the limit as the default, and F02-T24 sets the default (section 2). Only a wrong call reaches the limit, because counts stay far below it. |
| `use_utf8` on a Windows console, in Windows Terminal under Windows PowerShell 5.1 and PowerShell 7, and after `chcp 437`. | No CI machine has a Windows console, and a test reads output through a pipe, so it cannot see the console (architecture 10). v0.1-S25 has Troy check it by hand. F02-T70 checks a pipe, on both systems. |
| The two tables with one row in the F05 prototype "The language from the settings". | They keep the column widths of the whole recipe list, which `format_table` gives only with `min_widths` from the caller. F02-T50 tests `min_widths`. Which widths `list --tag` passes is for the F09 design, and v0.1-S21 checks those lines. F02-T61 rebuilds the F09 tables with one tag, whose rows hold the widest cells. |
| The two lines of the F13 prototype "Quantities that cannot be added". | They are an excerpt of a table whose other rows the prototype does not show, so their column width cannot be rebuilt from them. v0.1-S18 checks the amounts on those lines, and F02-T66 rebuilds the whole lists of F13. |
