# F14 Suggest a week menu: test plan

## 1. Feature

- ID and name: F14 Suggest a week menu
- Design: [design.md](design.md), version 1.0

## 2. Cases

The tests call `MENU_SUGGEST_COMMAND` of `recipe_menu.commands.suggest`, `Settings` and `read_settings` of `recipe_menu.settings`, `Context` of `recipe_menu.app`, `read_file_text` and `parse_toml` of `recipe_menu.datafile`, `main` of `recipe_menu.cli`, and `python -m recipe_menu`. A unit case calls `MENU_SUGGEST_COMMAND.run`, `Settings`, `read_settings`, `Context`, `read_file_text`, or `parse_toml` with values that it builds. A functional case runs `main` with a command line, as you type `recipe-menu menu suggest`. It passes no `commands`, so `main` uses the real `COMMANDS`, which holds `MENU_SUGGEST_COMMAND` after `MENU_SHOW_COMMAND` from the mock PR on (design choice 1). It passes a generator as `random`, as design 3.4 lets a test do. An integration case runs a v0.2 scenario at `main`, starts `python -m recipe_menu`, builds random weeks, or runs on the PT01 data folder. No case is a performance case (section 3). Each case names the part of the design that it comes from, such as (choice 7). The design's eight examples and their nine `# raises` lines are in F14-T01 (2.1), F14-T03 (2.2), F14-T22 (3.1), F14-T23 (3.2), F14-T25 (3.3 and 3.4), F14-T26 (3.5), and F14-T27 (3.6).

**Access that is denied.** No case denies access through the file system, with `os.chmod`, an access list, or `listing_denied` of `tests/f04_support.py`. The root user on Linux ignores the mode bits, so a test that relies on them fails as root. Every `PermissionError` in the cases comes from the fault harness, which raises it the same way for every user, or from Windows' refusal to replace a file that is open. So every case passes as root on Linux and as an administrator on Windows.

**How a case makes the disk fail.** The cases use `shop_faults(base, *rules)` of `tests/f13_support.py`, with the rules and the effects of the F13 test plan: `open P: E`, `write P: E`, `close P: E`, `move P: E`, `unlink P: E`, and `unlink P: later E`, and the effects `DENIED`, `IO`, `NO_SPACE`, and `CTRL_C`. F14 also uses the kind `read`. The harness of F08 records each open that is not in mode `x` as `read`, and a rule may name it: `read P: E` raises E in place of each read of P, and `read P: later E` lets the first read of P run and raises E in place of each later one. So `read menus/2026-W47.toml: later DENIED` lets `read_week_menu` read the file and makes the read of step 8 of 2.2 fail. A case that raises `KeyboardInterrupt` gets it back as exit code 130 from `main` through `call_main` of `tests/f08_support.py`, which turns a `KeyboardInterrupt` that leaves `main` into a failure.

The note for the Developer: the cases hold only when `read_file_text` reads the file through `io.open`, as `Path.read_bytes` and `open(path, "rb")` do in Python 3.13.18 on Troy's PC, so that the harness records the read and can fail it. A call that bypasses `io.open`, such as `os.open`, escapes the harness, and F14-T14 and F14-T26 fail. `menu suggest` writes only through `replace_file`, whose calls the F13 test plan names.

**The record of the reads.** F14-T09, F14-T10, F14-T11, F14-T12, F14-T14, F14-T19, and F14-T26 record which files `menu suggest` opens, removes, and moves, and which folders it lists, with `shop_faults(F.root)` and no rule unless the case gives one, as F13-T14 does. The harness records each open of a path under the data folder as `read`, or as `open` for mode `x`, each removal as `unlink`, and each move as `move A B`, with the paths relative to the folder and `/`. It records each listing by `os.scandir` or `os.listdir` in "the listings". `cli` reads `settings.toml` before it runs a command, so every record of a run of `main` starts with `read settings.toml`.

**Sources of random choices.** `menu suggest` calls `context.random.sample(C, k)` once and draws nothing else from the generator (choice 6). C is the candidates in ID order: the IDs that no dish of the week names, whose recipe reads with no error, and that have the tag when `--tag` is given. k is `min(need, len(C))`, where `need` is the sum of the dishes of the empty meals. The cases use three kinds of source, so that no case depends on the sequence that one Python version's `random.Random` gives for a seed:

- `Random(n)` is `random.Random(n)`. "The picks of `Random(n)`" are `Random(n).sample(C, k)`, which the test computes with the C and k of its run, as choice 6 says. No case writes a pick of a seed as a literal.
- A front source is a subclass of `random.Random` in `tests/f14_support.py`. Its `sample(population, k)` records the call as `(list(population), k)` and gives the first k items of the population. Any other draw from it, such as `random()`, `getrandbits`, `randrange`, `choice`, `choices`, or `shuffle`, fails the case.
- A back source is the same, but gives the last k items of the population, the last one first.

A line of `menu suggest` runs with a new front source unless the case names another source. With a front source, the new dishes are the candidates in ID order, so the expected files are literals.

These conventions hold for the calls of `main`:

- A line such as `menu suggest 2026-W48 --tag quick` in F with S stands for `suggest(home, F, "menu", "suggest", "2026-W48", "--tag", "quick", random=S)` of `tests/f14_support.py`. It adds `--data` and F, and runs `main` with `home`, `environ={}`, `today=date(2026, 11, 10)`, two new `io.StringIO` streams, no `commands`, and `random=S`. A line "on D" passes `today=D`. A line "with no folder" has no `--data`. A line that a rule can stop with `CTRL_C` runs through `call_main` of `tests/f08_support.py`, which passes no generator.
- A line of another command, such as `menu new 2026-W48` or `check`, runs through `at` of `tests/f09_support.py`, or `on` of `tests/f11_support.py` for a line "on D", with no generator. `--help` lines run through `call` of `tests/f07_support.py`.
- A word in quotation marks is one word, written as a Python string with its escapes, such as `""` or `" quick "`. Each `\uXXXX` in a word stands for that one character.
- The result is `(code, out, err)`. `(c, out L)` stands for `(c, out, "")`, where out is the lines of L, each followed by `"\n"`, and nothing more. `(c, err L)` stands for `(c, "", err)` in the same way. `(130, "", "")` is an exit with nothing written. The tests compare the whole texts.
- "The file" of a case is the menu file of the week of its line. "The file keeps its bytes and its time" means that its bytes and its `st_mtime_ns` after the line equal those before it.
- `STOP(W, M)` and `STOP_ZH(W, M)` are the three lines of `stop_at_error` in English and in Chinese, as the F09 test plan defines them, and `stop` of `tests/f09_texts.py` builds the result. W is a file, or a file and a place, such as `menus/2026-W47.toml, Monday dinner`.
- "Among the errors of `check`" has the meaning of the F09 test plan, and `assert_among_check` of `tests/f09_support.py` checks it.

The expected texts are these. The tests write each one out as a literal in `tests/f14_texts.py`, or build it there from literal templates. They import no message of `suggest`, `settings`, or `menus`, and never read a prototype file, because the messages are internal (design section 2, architecture 8). In each, W is a week such as `2026-W48`, T is the name of a tag in the language of the output, and a count of 1 takes the form for one: `meal`, `has`, and `stays`, in place of `meals`, `have`, and `stay`.

- `FIRST(W, n)` and `FIRST(W, n, T)` are the four lines of a first fill: `Filled n empty meals of W.`, or with T `Filled n empty meals of W with recipes that have the tag "T".`, then `No recipe appears twice in the week.`, `Run "recipe-menu menu show W" to see the week.`, and the swap line `To swap a dish, empty its meal in menus/W.toml, then run "recipe-menu menu suggest W" again.`. `FIRST_ZH(W, n)` and `FIRST_ZH(W, n, T)` are `已为 W 填好 n 个空餐。`, or with T `已为 W 填好 n 个空餐，用的都是带有标签“T”的菜谱。`, then `这一周里没有重复的菜谱。`, `运行“recipe-menu menu show W”查看这一周。`, and `要换掉一道菜，就在 menus/W.toml 里清空它那一餐，然后再运行“recipe-menu menu suggest W”。`.
- `REFILL(W, n, k)` and `REFILL(W, n, k, T)` are the two lines of a fill of every empty meal when k meals held dishes: the first line of `FIRST`, a space, and `Kept the k meals that already have dishes.`, then `Run "recipe-menu menu show W" to see the week.`. `REFILL_ZH` is the first line of `FIRST_ZH` followed by `保留了已经有菜的 k 餐。`, then `运行“recipe-menu menu show W”查看这一周。`.
- `SOME(W, f, e, k, why)` and `SOME(W, f, e, k, why, T)` are the two lines of a fill of f of the e empty meals, when k meals held dishes. The first line is `Filled f of e empty meals of W`, then ` with recipes that have the tag "T"` with T, then `.`, and when k is more than 0, a space and `Kept the k meals that already have dishes.`. The form of `meals` follows e. The second line, with c = e − f, is for why `left`: `c meals stay empty: no other recipe is left.`, or with T `c meals stay empty: no other recipe has the tag "T".`. For why `few`, it is `c meals stay empty: too few other recipes are left.`, or with T `c meals stay empty: too few other recipes have the tag "T".`. `SOME_ZH` has the first line `已为 W 填好 e 个空餐中的 f 个`, then `，用的都是带有标签“T”的菜谱` with T, then `。`, and when k is more than 0, `保留了已经有菜的 k 餐。`. ## 3. Performance cases

None. No F14 interface has a performance target. PT01 names `check`, `list`, `show`, `search`, `menu show`, and `shop`, and not `menu suggest` (requirements 7.1, design section 2). So `menu suggest` gets no timed case (R14). F14-T34 runs it on the PT01 data folder without timing it, as v0.2-S16 does. The PT01 cases of F07, F09, F10, F11, and F13 still run in every PR. They time the start of their commands, which from F14's implementation on imports `random` and makes one `Random()` (design choice 11).
