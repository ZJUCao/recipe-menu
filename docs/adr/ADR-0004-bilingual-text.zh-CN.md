# ADR-0004：提示、显示宽度和控制台

## 1. 状态

已接受。Troy 于 2026-11-10 批准 `docs/architecture.md`，接受了这条记录。

## 2. 背景

每条提示都有英文和中文（需求 7），F02 “保存工具所有提示的英文和中文”。原型里有几十条提示，分布在 16 个功能里，设计时还会再增加。如果把它们都放进一个文件，这个文件会随每个功能变长，逐渐逼近 500 行的限制（R06），而且 F02 之后的每个功能都得改 F02 的文件。表格在有中文时必须对齐；不论控制台代码页是什么，也不改任何 Windows 设置，中文都必须在 Windows Terminal 里正确显示。

## 3. 决定

- **提示。** 一条提示是 `text` 提供的 `Message` 值，有一个英文模板和一个中文模板，两者的占位符 `{name}` 完全相同。缺一种语言或占位符不同，创建时就会立即失败，所以任何引入该模块的测试都能发现它。每个模块把自己的提示放在自己的 `messages.py` 里。`text` 保存公用的提示，比如提醒运行 `--help` 的那一条。总体架构这样理解 F02 的“保存所有提示”：每条提示都是 F02 定义的类型的值，而这个类型不可能只有一种语言。
- **值的名称。** 一个值的两种语言的名称放在它的类型旁边：单位名在 `units`，餐名在 `settings`，星期名和月份名在 `menus`。`units` 把名称当作普通数据保存，因为它排在 `text` 前面。
- **宽度。** East Asian Width 为 W（宽）或 F（全角）的字符占两列。组合用的附加符号不占列。其他字符都占一列，包括 `“` 和 `×` 这类宽度不定的字符，因为 Windows Terminal 把它们画成一列宽。只有 `text` 计算宽度。
- **控制台。** 启动时，`cli` 请 `text` 把 stdout 和 stderr 设为 UTF-8。在 Windows 控制台上，Python 通过控制台的 Unicode 接口写入，所以代码页不起作用。重定向的输出是 UTF-8。

## 4. 考虑过的方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 每个模块的 `messages.py` 里放 `Message` 常量 | 每个功能只加自己的提示。缺一种语言会在该功能自己的测试里失败。mypy 检查每个提示名称。 | 工具的提示分散在很多文件里。 |
| `text` 里放一个提示文件 | 在一个地方就能读到所有提示。 | 它会逼近 R06 的限制。之后的每个功能都要改 F02 已经实现的文件。 |
| gettext 加 `.po` 文件 | 翻译的标准做法。 | 需要编译步骤和相应工具。英文原文就是键，改一个词就会让译文失效。引入时没有任何东西阻止缺少译文。 |
| TOML 提示文件 | 提示放在代码之外。 | 名称是字符串，打错字要到运行时才会发现。还要多写一个加载器。 |

## 5. 影响

- 每个功能的测试计划不需要 F02 帮忙，就能覆盖自己两种语言的提示。
- 表格的列在 Windows Terminal 里对齐。如果别的终端把宽度不定的字符画成两列宽，含这些字符的行就会错位。
- PowerShell 用管道传递或重定向输出时，会用 `[Console]::OutputEncoding` 解码这些 UTF-8 字节，所以只有这个编码是 UTF-8 时，中文才能完好地通过管道。终端里的输出和保存的购物清单不受影响。
