# ADR-0005：自己写命令行解析器，不用 argparse

## 1. 状态

已接受。Troy 于 2026-11-10 批准 `docs/architecture.md`，接受了这条记录。

## 2. 背景

F05 的原型定下了两种语言的帮助文字，以及命令行写错时的提示，比如 `--lang must be en or zh, not "fr".` 和 `Unknown command "cook".`，退出码都是 2。`--lang` 可以出现在命令行的任何位置，比如 `recipe-menu --help --lang zh`，而错误提示必须使用这种语言。语法很小：一到两个命令词、位置参数、带值的选项 `--lang`、`--data`、`--tag` 和 `--servings`，以及开关 `--help` 和 `--version`。`argparse` 会输出它自己的英文用法和错误文字，比如 `error: argument --lang: invalid choice: 'fr'`，帮助也是它自己的排版。

## 3. 决定

`cli` 自己解析命令行。每个 `Command` 声明自己的命令词、位置参数和选项。解析器先找 `--lang`，这样它自己的错误提示就用所选语言输出。然后它找到命令，按命令的声明检查参数和选项，遇到任何错误都抛出带 `Message` 的 `UsageError`。帮助由各命令的帮助行生成，排版与 F05 原型相同。选项的值是紧跟其后的下一个参数。解析器不接受缩写。

## 4. 考虑过的方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 在 `cli` 里自己写解析器 | 每条提示和帮助都来自两种语言的 `Message` 值。每个命令解析选项的方式都一样。 | F05 要编写并测试几百行代码，在 R04 和 R06 的限制之内。 |
| `argparse`，覆盖它的 `error` 方法，帮助文字自己写 | 在标准库里。支持很多种选项写法。 | 它的错误以写好的英文文字传给 `error`，要变成我们的提示就得匹配这些文字，而这些文字可能随 Python 版本变化。缩写和帮助排版都得关掉。 |
| click 或 typer | 命令定义写起来短。 | 是 R16 下的依赖。它们的提示也是英文的，问题和 `argparse` 一样。 |

## 5. 影响

- 帮助和用法错误在两种语言下都和 F05 原型完全一样。
- 命令的新选项在它的 `Command` 里声明，解析器直接处理，不用改 `cli`。
- `argparse` 接受而原型从未出现的写法，比如 `--lang=zh` 或 `-l zh`，除非 F05 的设计加上，否则不支持。
