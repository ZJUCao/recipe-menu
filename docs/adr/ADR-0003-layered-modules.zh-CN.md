# ADR-0003：分层的模块，每个模块是一个只有一个接口文件的文件夹

## 1. 状态

已接受。Troy 于 2026-11-10 批准 `docs/architecture.md`，接受了这条记录。

## 2. 背景

R07 按总体架构里的模块表检查引用，所以每个模块需要准确的路径规则和一组接口文件。16 个功能按拓扑顺序一个一个地做，每个功能的设计者只看得到排在它前面的功能。一个文件最多 500 行（R06），一个源代码 PR 最多改 5 个文件（R03）。测试需要固定的日期、自己的数据文件夹，以及代替控制台的字符串流。

## 3. 决定

- 包 `recipe_menu` 分五层：基础层（`lang`、`units`、`text`、`datafile`）、领域层（`catalog`、`recipes`、`settings`、`menus`、`shopping`）、应用层（`app`）、命令层（每个命令类功能一个模块，放在 `commands/` 下）和入口层（`cli`）。一个模块只依赖更低的层，以及总体架构点名的本层模块。
- 每个模块是一个文件夹。它的 `__init__.py` 是其他模块唯一可以引用的文件，文件夹里的其他文件都是内部的。
- 只有 `cli` 读取命令行、环境、日期和控制台。它通过 `Context` 把这些传下去。
- 每个命令模块定义自己的 `Command` 值，`cli` 保存命令列表。命令类功能在自己的 mock PR 里把自己加进这个列表。
- `shopping` 不读任何文件，所以只用值就能测试购物清单的规则。

## 4. 考虑过的方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 每个模块一个文件夹，以 `__init__.py` 为接口 | R07 能抓住任何对模块内部文件的引用。模块拆成更多文件时不用改表格。 | 每个模块都需要一个列出公开名称的 `__init__.py`。 |
| 每个模块一个文件，比如 `units.py` | 文件更少。 | 文件超过 500 行（R06）时，拆分会改变表格里的路径，这就是要 Troy 批准的架构变更。 |
| 一个扁平的包，没有模块表 | 没有要维护的东西。 | R07 什么也检查不了，任何文件都可以引用任何文件。 |
| 由命令自己读取环境 | 要传递的东西更少。 | 测试就得替换时钟、环境和控制台。 |

## 5. 影响

- PR 一旦引用别的模块的内部文件、向上引用或造成循环，R07 就判它失败。
- 这些层在 v0.2 里依然成立。`suggest`、`add` 和 `edit` 作为命令模块放进来，不用改表格。
- 有两个功能使用更早的功能创建的模块，这超出了需求的依赖图：F02 使用 F01 的 `lang`，F05 使用 F03 的 `datafile`。
- 每个命令类功能都要在 F05 负责的 `cli` 里改一行。这一行是命令和入口之间唯一的耦合。
- 命令模块可以依赖所有领域模块。设计审查检查一个命令只用到它需要的部分。
